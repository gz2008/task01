CTFHub - Web - 信息泄露 - 备份文件下载 - bak

# CTFHub # Web # 信息泄露 # 备份文件下载 # bak

一、题目信息

  • 题目名称：bak
  • 题目方向：Web - 信息泄露 - 备份文件下载
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目提示：Flag in index.php source code.

二、解题工具

  • 浏览器：查看首页提示和源码备份内容。
  • cURL：探测备份文件并读取源码。

三、解题思路与步骤

  1. 分析首页提示：访问题目根路径后，页面标题为 CTFHub 备份文件下载 - bak，正文提示 Flag 位于 index.php 的源代码中。
  2. 推断备份文件名：题目类型为 bak，说明开发者可能将 index.php 的备份留在了 Web 目录下。常见备份形式包括 index.php.bak、index.bak、index.php~ 和 index.php.swp。
  3. 探测备份文件：访问 /index.php.bak，服务器返回 200 OK，响应类型为 application/x-trash，说明备份文件确实存在： 
    curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/index.php.bak"
  4. 读取泄露源码：备份文件没有经过 PHP 解析，因此可以直接看到原始 PHP 代码。响应内容中保留了如下注释： 
    // FLAG: ctfhub{a7fe47252418e59cb7789393}
  5. 获取 Flag：从源码注释中提取完整 Flag 并提交。

四、最终 Flag

ctfhub{a7fe47252418e59cb7789393}

五、解题总结

  • 备份文件不能存放在 Web 根目录：.bak、~、.swp 等编辑器或备份文件通常以静态文本提供，不会被 PHP 解析，能够直接泄露源码。
  • 根据题目提示缩小范围：题目明确指出 Flag 在 index.php 源码中，可以围绕该文件名尝试常见备份后缀。
  • 关注响应类型和状态码：200 OK 与 application/x-trash 说明请求到的不是普通 HTML 页面，而是源代码备份。
  • 源码注释也可能包含敏感信息：开发、调试期间写入的注释同样可能造成信息泄露。
