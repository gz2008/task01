CTFHub - Misc - 流量分析 - Redis流量

# CTFHub # Misc # 流量分析 # Wireshark # Redis

一、题目信息

  • 题目名称：Redis流量
  • 题目方向：Misc - 流量分析
  • 题目附件：redis.pcap

二、解题工具

  • Wireshark (网络协议分析器)

三、解题思路与步骤

  1. 下载附件并导入：将附件 redis.pcap 下载到本地，使用 Wireshark 打开。
  2. 过滤流量：Wireshark 对 Redis 的解析协议名并非 "redis"，而是 RESP（Redis序列化协议）。因此，在顶部显示过滤器栏中输入 resp 并回车，或直接过滤默认端口 tcp.port == 6379。
  3. 追踪 TCP 流：选中任意一个 RESP 数据包，右键点击 -> 选择 追踪流 (Follow) -> TCP 流 (TCP Stream)。
  4. 分析数据流：Redis 通信是明文传输的。在追踪流窗口中，可以看到一系列 Redis 命令。发现出题人使用了两次 SET 命令，将 Flag 拆分成了两部分：
    • 第一个命令：SET F14g1 $22 ctfhub{6051d6123de43df（前半段）
    • 第二个命令：SET flag2 $18 ad7609804925c0121}（后半段）
  5. 拼接 Flag：将两部分字符串按顺序拼接，得到完整的 Flag。

四、最终 Flag

ctfhub{6051d6123de43dfad7609804925c0121}

五、解题总结

这道题延续了流量分析的基础套路，但考察了两个新的知识点：

  • 协议辨析：Wireshark 中 Redis 对应的协议名是 RESP。如果不清楚，可以使用默认端口 tcp.port == 6379 作为万能替代方案。
  • 拆分 Flag 的套路：出题人常把 Flag 拆散存放在不同位置（如多个数据库键值中），要求选手仔细阅读所有的命令交互记录，并进行拼接。
  • Redis 明文特性：与 MySQL 的二进制协议不同，Redis 的 RESP 协议是以纯文本形式交互的，追踪流后所见即所得，非常适合新手练习。
