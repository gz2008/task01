CTFHub - Misc - 流量分析 - Length

# CTFHub # Misc # 流量分析 # Wireshark # ICMP

一、题目信息

  • 题目名称：Length
  • 题目方向：Misc - 流量分析
  • 题目附件：icmp_len.pcap

二、解题工具

  • Wireshark (网络协议分析器)

三、解题思路与步骤

  1. 导入并过滤：将附件 icmp_len.pcap 导入 Wireshark，在显示过滤器栏输入 icmp 并回车。观察到 Length 列的数据包长度参差不齐，并非正常的固定长度，提示我们答案可能隐藏在数据包的大小中。
  2. 计算有效数据长度：由于 Wireshark 显示的 Length 是整个数据帧的总长度，我们需要减去协议头部长度：
    • Ethernet II 头部：14 字节
    • IPv4 头部：20 字节
    • ICMP 头部：8 字节
    • 总计头部开销：14 + 20 + 8 = 42 字节
    • 因此，真实的数据长度 = Length - 42。
  3. 提取与转换：点击 Time 列按时间排序，依次提取每个 ping 请求包（Request） 的长度并减去 42，将其结果作为 ASCII 码转换为字符。例如：
    • 包长为 141 -> 141 - 42 = 99 -> ASCII 码对应 'c'
    • 包长为 158 -> 158 - 42 = 116 -> ASCII 码对应 't'
    • 包长为 144 -> 144 - 42 = 102 -> ASCII 码对应 'f'
    • 包长为 146 -> 146 - 42 = 104 -> ASCII 码对应 'h'
  4. 拼接 Flag：按顺序将所有减后结果转换为字符并拼接，直到最后一个包长 167（167 - 42 = 125 -> '}'），即可得到完整的 Flag。

四、最终 Flag

ctfhub{acb659f023}

五、解题总结

这道题展示了 ICMP 数据外带的另一种变种思路：通过数据包长度进行隐蔽通信。

  • 常规的隐写题往往将数据藏在 Data 字段的具体内容（十六进制字节）中，而本题反其道而行之，将信息编码在了包的长度属性上。
  • “偷懒”小技巧：做题时不必每次心算减去 42。在 Wireshark 下方的详情面板中，展开 Internet Control Message Protocol，可以直接看到 Data (XX bytes) 这一行，括号里的 XX 数字就是已经扣除头部开销后的真实数据长度，直接拿去转换即可。
  • 这提醒我们在流量分析中要拓宽思路，数据的外带方式多种多样（内容、长度、时间间隔等），不要局限于表面的 Payload 本身。
