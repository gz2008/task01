CTFHub - Web - 信息泄露 - SVN泄露

# CTFHub # Web # 信息泄露 # SVN # PRISTINE

一、题目信息

  • 题目名称：SVN泄露
  • 题目方向：Web - 信息泄露
  • 题目环境：动态分配的 HTTP 服务地址
  • 题目提示：开发人员使用 SVN 进行版本控制，如果部署时将 .svn 目录发布到线上，就可能造成源码和历史版本泄露。
  • 题目目标：恢复旧版本源码，读取已从最新目录删除的文件。

二、漏洞原理

SVN 1.7 及以上版本使用工作副本数据库 .svn/wc.db 保存文件和目录的版本信息，文件原始内容则按 SHA-1 存放于 .svn/pristine/。即使某文件已经从网站根目录删除，只要对应的 pristine 对象仍可访问，就能恢复其内容。

数据库中的 NODES 表描述当前工作副本节点，PRISTINE 表保存原始对象的校验和与大小。通过节点对应的 checksum，可以计算 pristine 文件路径：.svn/pristine/<前2位>/<完整SHA-1>.svn-base。

三、探测泄露

先访问首页与常见的 SVN 元数据文件：

curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/"
curl.exe -i "http://challenge-xxx.sandbox.ctfhub.com:10800/.svn/entries"

首页提示 flag 位于旧版本源码中，.svn/entries 返回状态码 200，确认 .svn 目录可被公开访问。随后下载工作副本数据库：

curl.exe -o wc.db "http://challenge-xxx.sandbox.ctfhub.com:10800/.svn/wc.db"

本次响应中的 wc.db 大小为 122880 字节，属于 SVN 1.7+ 工作副本格式。

四、分析 wc.db

使用 SQLite 查询文件和原始对象记录：

sqlite3 wc.db "SELECT local_relpath, kind, revision, checksum FROM NODES;"
sqlite3 wc.db "SELECT checksum, size, refcount FROM PRISTINE;"

关键结果如下：

flag_2879815809.txt | file | 3 |
index.html           | file | 1 | $sha1$bf45c36a4dfb73378247a6311eac4f80f48fcb92

$sha1$bf45c36a4dfb73378247a6311eac4f80f48fcb92 | 221 | 1
$sha1$c4c14acebfaa268d6688480a9f84dcf9d377b379 |  33 | 0

flag_2879815809.txt 已不在网站当前目录中，直接访问返回 404。它对应的大小为 33 字节的 pristine 对象 c4c14ace...，说明旧内容仍保留在工作副本数据库中。

五、恢复旧版本文件

根据校验和构造 pristine 路径并下载：

curl.exe "http://challenge-xxx.sandbox.ctfhub.com:10800/.svn/pristine/c4/c4c14acebfaa268d6688480a9f84dcf9d377b379.svn-base"

响应内容即为被删除文件的原始内容：

ctfhub{1f14f4a8fd41c5eb0eee9eae}
如果只拿到 wc.db 而无法确定目标对象，可先联合分析 NODES 与 PRISTINE，再根据 checksum 下载对应 .svn-base。SVN 1.6 及更早版本则主要依赖 .svn/entries 和 .svn/text-base/。

六、最终 Flag

ctfhub{1f14f4a8fd41c5eb0eee9eae}

七、修复建议

  • 禁止 Web 服务器访问 .svn、.git、.hg 等版本控制目录。
  • 部署时只发布构建产物，不要把工作副本或完整源码目录直接放到 Web 根目录。
  • 使用 Nginx 或 Apache 显式拦截隐藏目录及 SVN 元数据路径。
  • 敏感文件一旦进入版本控制，应立即轮换其中的密钥、密码或 flag，并清理历史对象。

八、解题总结

本题关键在于识别 SVN 1.7+ 的 wc.db 与 pristine 对象机制。虽然目标文件已从当前站点删除，但数据库仍保留了文件校验和，直接获取对应 pristine 对象即可恢复 flag。
