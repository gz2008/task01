Pikachu - XSS 之盲打

分类：Web / XSS · 环境：本机 Pikachu 靶场 · 题目路径：Cross-Site Scripting → xss 之盲打

仅在自己部署的 127.0.0.1 靶场练习；验证载荷只弹出数字，不读取或发送后台 Cookie。

一、题目流程

访问 /pikachu/vul/xss/xssblind/xss_blind.php，提交反馈内容和姓名。前台不会显示反馈列表，页面只返回“已经收到”的提示。题目提示后台地址为 /pikachu/vul/xss/xssblind/admin_login.php。

二、源码与漏洞成因

前台写入数据库前做了 SQL 转义，但后台列表取出数据后直接拼接表格 HTML：

$content = escape($link, $_POST['content']);
$name = escape($link, $_POST['name']);
$query = "insert into xssblind(time,content,name)
          values('$time','$content','$name')";

// admin.php
<td>{$data['content']}</td>
<td>{$data['name']}</td>

因此攻击者提交的内容被持久化，管理员进入后台查看列表时才触发，这就是“盲打”：提交者无法在前台直接看到执行结果。

三、验证步骤

  1. 提交内容 <script>alert(1)</script>，姓名填写普通文本。
  2. 使用题目提示的后台测试账号 admin / 123456 登录管理页面。
  3. 打开反馈列表，观察恶意内容被放入表格单元格。
  4. 若出现数字 1 弹窗，说明脚本在后台管理员页面执行。

验证时应把前台提交成功和后台执行成功分开记录；只有第二阶段能证明盲打 XSS 的完整影响链路。

四、风险与修复

后台通常拥有更高权限，盲打 XSS 可能影响审核人员或管理员。修复时应在后台输出点使用：

$content = htmlspecialchars(
    $data['content'],
    ENT_QUOTES | ENT_SUBSTITUTE,
    'UTF-8'
);
$name = htmlspecialchars(
    $data['name'],
    ENT_QUOTES | ENT_SUBSTITUTE,
    'UTF-8'
);

同时为后台设置严格的 CSP、HttpOnly Cookie 和最小权限。不要把“前台看不到结果”误认为没有漏洞。
