Pikachu - SQL 注入 - Insert/Update 注入

分类：Web / SQL Injection · 环境：本机 Pikachu 靶场 · 题目路径：SQL-Inject → insert/update 注入

一、漏洞成因

登录后，编辑资料接口直接使用 $_POST 拼接 UPDATE 语句，没有调用转义函数：

$getdata = $_POST;
$query = "update member set sex='{$getdata['sex']}',
phonenum='{$getdata['phonenum']}', address='{$getdata['add']}',
email='{$getdata['email']}' where username='{$_SESSION['sqli']['username']}'";

二、验证过程

先用题目内置会员 vince/123456 登录，再在 add 字段提交：

test-address',sex='injected

该输入会闭合 address 字符串并额外写入 sex 字段。提交请求在本地返回 302 并跳转到 sqli_mem.php，说明 UPDATE 分支被执行。当前绿色环境的旧式 MYSQL_ASSOC 用法会影响会员页回显，因此这里只把 302 和源码路径作为验证证据，不虚构页面最终值。

三、Insert 的同类风险

注册接口同样直接拼接 INSERT 语句。字段未参数化时，输入可以改变列值或增加 SQL 语句片段。

四、修复建议

所有 INSERT、UPDATE 都使用预处理语句；对每个字段做长度、类型和业务校验，并限制当前用户只能修改允许的列。
