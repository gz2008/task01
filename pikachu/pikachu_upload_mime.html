Pikachu - 不安全文件上传 MIME 检查

分类：Web / File Upload / MIME Bypass · 环境：本机 Pikachu 靶场 · 题目路径：Unsafe File Upload → MIME type

本文只记录本地授权靶场验证，不针对任何外部系统。会话、Cookie、数据库凭据和真实业务数据均已省略。

一、功能观察

服务端只允许 image/jpg、image/jpeg、image/png，但不检查真实内容和扩展名。

二、漏洞成因与验证思路

代码依赖客户端提供的 $_FILES['type']，同时保留上传时的原始文件名。

POST /pikachu/vul/unsafeupload/servercheck.php
Content-Type: image/png
filename: local-marker
body: &lt;?php echo 'PIKA_SERVER_OK'; ?&gt;
响应返回保存路径；访问后输出 PIKA_SERVER_OK。测试文件已删除。

三、影响

伪造 Content-Type 即可把非图片文件保存为服务端可执行文件。

四、修复建议

不要信任请求声明的 MIME；使用 fileinfo 或 getimagesize 检查真实内容，并强制安全扩展名。

五、复盘

本关的关键不是记住单个字符串，而是确认输入经过的边界：它进入的是 SQL、Shell、文件系统、HTML 还是 URL 处理器。根因确认后，最小验证应聚焦一个可观察结果，再决定是否需要升级利用链。
