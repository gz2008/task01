Pikachu - 暴力破解 - 客户端验证码绕过

# Pikachu# Web# 客户端校验# Burp Suite

一、题目信息

  • 题目名称：验证码绕过（on client）
  • 题目路径：Pikachu → 暴力破解 → 验证码绕过（on client）
  • 访问地址：http://127.0.0.1/pikachu/vul/burteforce/bf_client.php
  • 目标：绕过客户端验证码限制，并验证登录请求可被重放。
本文仅记录本地 Pikachu 靶场实验，不针对任何未授权系统。示例中的会话 Cookie 已省略。

二、发现客户端校验

访问 bf_client.php 后，在 Burp 的 HTTP history 中查看响应源码。登录表单包含：

<form id="bf_client" method="post"
      action="bf_client.php" onsubmit="return validate();">
    <input name="username">
    <input name="password">
    <input name="vcode">
</form>

关键是 onsubmit="return validate();"：提交前由浏览器执行 JavaScript，而不是先由服务端验证。

三、漏洞原理

页面中的验证函数读取输入框，并与前端变量 code 比较：

function validate() {
    var inputCode = document.querySelector('#bf_client .vcode').value;
    if (inputCode.length <= 0) {
        return false;
    } else if (inputCode != code) {
        createCode();
        return false;
    } else {
        return true;
    }
}

验证码答案保存在客户端 JavaScript 变量中。校验失败时只是返回 false，阻止浏览器提交表单；客户端代码、JavaScript 和请求都可以被用户修改。

四、抓取有效登录请求

  1. 在页面中输入账号、密码，并填写一次正确的图片验证码。
  2. 点击登录，在 Burp 的 Proxy → HTTP history 中找到 POST /pikachu/vul/burteforce/bf_client.php。
  3. 右键选择 Send to Repeater，确认响应中出现登录结果。

请求体形式如下，Cookie 只保留当前本地会话：

username=admin&password=123456&vcode=<valid-code>&submit=Login

五、使用 Burp 绕过

在 Repeater 中直接修改请求参数，不经过浏览器的 validate()：

username=admin&password=123456&vcode=wrong&submit=Login

如果响应仍然返回登录成功，说明服务端没有真正校验验证码。即使服务端保留了验证码字段，攻击者也可以先抓取一个有效请求，再在 Burp 中反复重放和修改密码。

六、使用 Intruder 验证弱口令

  1. 在有效 POST 请求上右键，选择 Send to Intruder。
  2. 进入 Positions，点击 Clear §。
  3. 只标记密码值：
username=admin&password=§123456§&vcode=<valid-code>&submit=Login
  1. 在 Payloads 中选择 Simple list 并加载密码字典。
  2. 在 Settings → Grep - Match 添加 login success。
  3. 点击 Start attack，观察命中成功关键字的请求。

七、漏洞影响与修复

  • 前端校验不能作为安全边界，攻击者可以禁用 JavaScript 或直接构造 HTTP 请求。
  • 验证码答案不能放在前端变量中，必须由服务端保存并校验。
  • 验证码应设置有效期、使用后销毁，并配合登录限速和失败次数限制。

八、总结

本题的核心不是识别验证码图片，而是发现验证码校验只发生在客户端。通过 Burp 抓到真实 POST 请求后，可以绕过浏览器的 JavaScript 限制并测试登录接口。安全校验必须在服务端完成，前端校验只能改善用户体验，不能防止攻击。
