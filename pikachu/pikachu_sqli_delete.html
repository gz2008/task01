Pikachu - SQL 注入 - Delete 注入

分类：Web / SQL Injection · 环境：本机 Pikachu 靶场 · 题目路径：SQL-Inject → delete 注入

一、漏洞成因

if(array_key_exists('id', $_GET)){
    $query = "delete from message where id={$_GET['id']}";
    execute($link, $query);
}

删除链接中的 id 没有执行 is_numeric 校验，用户可以直接控制 DELETE 的 WHERE 条件。

二、验证过程

先提交一条只用于测试的留言，再将删除请求中的 id 改为条件表达式：

GET /pikachu/vul/sqli/sqli_del.php?id=0 OR content LIKE 'writeup-delete-test%'

本地测试请求返回 302 Found，响应位置为 sqli_del.php，说明删除语句执行了。验证数据使用独立测试留言，测试后应清理。

三、修复建议

服务端将 id 转换为整数并使用参数化 DELETE；同时增加登录、权限和 CSRF 校验，不能把“知道链接”当成删除权限。
