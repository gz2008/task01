Pikachu - DOM 型 XSS-X

分类：Web / XSS · 环境：本机 Pikachu 靶场 · 题目路径：Cross-Site Scripting → DOM 型 xss-x

仅在自己部署的 127.0.0.1 靶场练习；测试脚本只弹出数字，不读取或发送数据。

一、入口与数据流

访问 /pikachu/vul/xss/xss_dom_x.php，提交表单后地址栏会出现 text=...。点击页面中的链接时，JavaScript 从 window.location.search 取出参数，并写入 div#dom。

二、源码与成因

var str = window.location.search;
var txss = decodeURIComponent(str.split("text=")[1]);
var xss = txss.replace(/\+/g, ' ');
document.getElementById("dom").innerHTML =
    "<a href='" + xss + "'>就让往事都随风</a>";

这里的危险源是 URL 查询字符串，危险 sink 是 innerHTML。服务端仅输出页面框架，实际注入和执行完全发生在浏览器端。

三、构造与验证

可直接访问下面的本地测试 URL：

http://127.0.0.1/pikachu/vul/xss/xss_dom_x.php?text='%3E%3Cimg%20src%3D%22%23%22%20onmouseover%3D%22alert(1)%22%3E

点击页面中的提交按钮或生成的链接，随后将鼠标移到插入的图片位置。若弹出 1，说明 URL 参数已被解码并作为 HTML 执行。Elements 面板可用于确认原始标签进入了 DOM。

四、与反射型 XSS 的区别

  • 反射型 XSS 的危险字符串通常由服务端放入响应 HTML。
  • 本题的服务端不需要把参数原样反射；前端脚本从 URL 读取参数并生成 HTML。
  • 修复重点是浏览器端数据流，尤其是避免 innerHTML 拼接。

五、修复思路

使用 URLSearchParams 读取参数，并通过安全 DOM API 设置链接地址和文本：

const value = new URLSearchParams(location.search).get("text") || "";
const link = document.createElement("a");
link.href = value;
link.textContent = "就让往事都随风";
document.getElementById("dom").replaceChildren(link);

还应限制可接受的协议，例如只允许 https: 或 http:，避免把危险协议写入 href。
