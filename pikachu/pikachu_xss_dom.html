Pikachu - DOM 型 XSS

分类：Web / XSS · 环境：本机 Pikachu 靶场 · 题目路径：Cross-Site Scripting → DOM 型 xss

仅在自己部署的 127.0.0.1 靶场练习；测试脚本只弹出数字，不读取或发送数据。

一、页面逻辑

访问 /pikachu/vul/xss/xss_dom.php，在输入框填写内容并点击按钮。页面不会把输入提交给服务端，而是由浏览器中的 JavaScript 读取输入框，再写入 div#dom。

二、漏洞成因

function domxss(){
    var str = document.getElementById("text").value;
    document.getElementById("dom").innerHTML =
        "<a href='" + str + "'>what do you see?</a>";
}

用户输入被拼接进 HTML 属性，且写入 API 是 innerHTML。服务端没有参与危险字符串的生成，因此这是 DOM 型 XSS：数据流从 DOM 输入点到危险 DOM sink 完成。

三、构造与验证

在输入框提交下面的测试载荷：

'><img src="#" onmouseover="alert(1)">

载荷先闭合原有的 href，再插入新的元素和事件属性。点击按钮后，查看 Elements 面板可以看到生成的 HTML；将鼠标移到图片区域时，若出现数字 1 的弹窗，说明脚本执行成功。

四、修复思路

如果目标只是展示链接文本，应避免拼接 HTML，改用 DOM API 设置属性：

var link = document.createElement("a");
link.href = str;
link.textContent = "what do you see?";
document.getElementById("dom").replaceChildren(link);

如果业务确实需要 HTML，应使用严格的白名单清洗，并避免把不可信字符串直接放入事件属性、脚本上下文或 HTML 属性中。
