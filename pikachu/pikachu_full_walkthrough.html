Pikachu 全模块通关验收总览：从参数边界到完整攻击链

分类：Web / 综合复盘 · 环境：本机 Pikachu 靶场 · 日期：2026-10-24

本文只记录本机靶场中的授权测试。文章不包含真实会话、密码、Cookie、私钥或可复用的外部目标信息。 标记文件、越权测试用户和后台测试记录均在验证后清理。

一、验收结论

前 18 篇已经分别覆盖暴力破解、XSS、CSRF 和 6 类 SQL 注入。本轮把其余模块合并验收， 对靶场 vul/ 下的 91 个 PHP 入口做了状态扫描：全部返回 200 或预期的 302， 没有出现 500 或其他异常状态。

可验证攻击链：盲注、宽字节注入、HTTP 头注入、命令执行、代码执行、 LFI/RFI、任意文件下载、客户端/MIME 上传绕过、水平与垂直越权、目录遍历、敏感信息泄露、 PHP 反序列化、XXE、开放重定向、SSRF 以及 XSS 后台接收端均已得到实际回显或数据落库证据。

有两类页面本来就是用来展示防护措施的，不能为了“通关”而虚构绕过： CSRF Token 会生成隐藏字段并参与服务端比较；getimagesize() 页面还检查后缀白名单， 本轮直接提交可执行扩展名会被拒绝。它们应作为“防护生效”记录，而不是漏洞成功记录。

三、关键利用链

1. SQL 注入：从报错到无回显

盲注页没有显示数据库错误，返回页面只区分“查到一行”和“没查到”。 因此先构造真假条件，再用响应时间验证可执行表达式： 

name=vince' and substr(database(),1,7)='pikachu'--
name=vince' and substr(database(),1,7)='wrong'--
name=vince' and if(substr(database(),1,7)='pikachu',sleep(2),0)--
submit=查询

宽字节页面先把输入交给转义函数，再把数据库客户端字符集切换为 GBK。 攻击者提交的 %df%27 会被合并为特殊字节序列，使闭合引号恢复为 SQL 语法： 

name=%df%27 union select 1,2%23
submit=查询

HTTP 头页面把 User-Agent 写进 INSERT。把第三个字段闭合后插入时间表达式： 

User-Agent: pika',sleep(2),'audit') --

GET /pikachu/vul/sqli/sqli_header/sqli_header.php

上述路径的共同根因都是“数据被拼成 SQL 语法”。只转义引号并不够； 正确做法是参数化查询，并让字符集在连接建立时保持一致。

2. 命令执行与代码执行

ping 页面执行的是字符串拼接后的系统命令。把目标地址和后续命令分开后， 可以看到命令注入的明确回显： 

ipaddress=127.0.0.1& echo PIKA_RCE_PING_OK
submit=ping

eval 页面则把输入当成 PHP 语句执行。验证时只输出固定标记，不读取文件、不建立连接： 

txt=echo 'PIKA_RCE_EVAL_OK';
submit=提交

结论不是“过滤几个符号”，而是禁止把用户输入放进 shell 或动态代码； 使用参数数组调用外部程序，并彻底移除动态 eval。

3. 文件包含、下载与上传

本地文件包含入口会把 filename 直接交给 include。 在本机 Windows 环境中，目录穿越可以读到系统文本文件： 

filename=../../../../../../Windows/win.ini
submit=submit

远程文件包含则把同一个参数交给 HTTP。用一个仅返回固定标记的本地回调服务， 可以观察到靶场确实代用户发起了请求并处理了返回内容： 

filename=http://127.0.0.1:18080/rfi
submit=submit

不安全下载用 download/ 作为前缀，但没有规范化最终路径。 穿越后可以通过附件响应读取配置文件： 

GET /pikachu/vul/unsafedownload/execdownload.php
filename=../../../inc/config.inc.php

客户端上传页面只有浏览器端扩展名检查，拦截或重放请求即可绕过。 服务端 MIME 页面只相信请求声明的 Content-Type，并保留原始文件名。 测试文件只输出固定标记，验证后已立即删除： 

Content-Type: image/png
filename: local-marker
body: <?php echo 'PIKA_UPLOAD_OK'; ?>

getimagesize() 页面应先确认后缀为 jpg/jpeg/png，再校验 MIME、真实图片和大小。 本轮使用真正图片测试时，使用可执行扩展名会被后缀白名单拒绝，因此不把该关写成 RCE。 即使图片校验存在缺陷，也必须配合上传目录执行、解析器差异或后续文件包含才可能扩大影响。

本地测试中生成的标记上传物已删除，避免靶场长期保留可执行测试文件。

4. 越权与身份边界

op1 只确认当前用户已登录，却把查询对象交给 URL 参数 username。替换参数即可从一个账户读取另一个账户的资料，这是水平越权。 

GET /pikachu/vul/overpermission/op1/op1_mem.php
username=kobe
submit=点击查看个人信息

op2 的普通用户能直接打开管理编辑页。服务端只检查 check_op2_login()，没有再次校验 level == 1； 本轮以低级别用户提交管理表单，数据库出现测试用户后再清理。

修复原则是服务端从会话中取得当前主体，并在每一次对象访问或功能调用时同时检查 “是谁”和“是否有权限”，而不是信任隐藏字段、URL 或前端菜单。

5. 解析器与数据信任

目录遍历把 title 直接拼到 require "soup/$filename"。 文件包含与目录遍历的实质相同：边界检查应发生在路径规范化之后， 并使用固定文件列表或安全的基目录约束。

PHP 反序列化页面允许客户端控制对象属性，随后把属性回显到 HTML： 

O:1:"S":1:{s:4:"test";s:25:"<script>alert(1)</script>";}

XXE 页面在解析 XML 时启用了外部实体。把实体指向本机文本文件， 响应中的结果证明实体被展开： 

<?xml version="1.0"?>
<!DOCTYPE ANY [<!ENTITY f SYSTEM "file:///C:/Windows/win.ini">]>
<x>&f;</x>

对应修复分别是：不使用用户输入选择文件；不在业务对象上调用不可信的反序列化； 解析 XML 时禁用 DTD 和外部实体。

6. 客户端与网络侧信任

开放重定向接口把 url 原样放入 Location。 测试使用不属于任何真实目标的示例域名，只观察 302 响应，不跟随跳转。 

GET /pikachu/vul/urlredirect/urlredirect.php?url=https%3A%2F%2Fexample.com%2F

SSRF 的两种实现分别使用 curl 和 file_get_contents()。 本地回调服务返回固定字符串，证明请求由靶场服务器而非浏览器发出； file 包装器测试则证明输入可以访问本地文件。生产环境应使用目标域名白名单、 DNS 解析后地址校验、协议限制和重定向后的二次校验。

7. XSS 后台接收端

对 Cookie 收集、键盘记录和钓鱼结果接收端分别提交了不含真实凭据的测试标记， 登录管理后台后三组标记都出现在对应列表中，随后通过数据库清理。 这说明前端漏洞一旦能在受害者浏览器中执行，就可能把当前页面的数据带到攻击者的收集端。

本地版本中，钓鱼中转页和键盘脚本保留了上游写死的回调地址，因此浏览器端的完整跳转链 需要改成当前实验地址后才能运行；接收端的写入和读取逻辑已经单独验证。 这不影响对漏洞根因的判断，但不能把未完成的前端跳转写成成功。

四、修复优先级

风险面最低限度修复
SQL 注入全部改为参数化查询；字符集固定为 UTF-8；停止拼接表名和列名
命令 / 代码执行使用参数数组调用进程；禁止把输入交给 shell；移除动态 eval
文件操作路径规范化、固定基目录、白名单、禁止远程 include、下载使用映射 ID
上传服务端验证真实格式和大小；随机文件名与安全扩展名；上传目录禁止脚本执行
越权会话绑定主体；对象级和功能级双重授权；服务端校验角色级别
反序列化 / XML不接受客户端对象；使用 JSON；禁用 DTD 和外部实体
URL / SSRF重定向只允许相对路径；SSRF 使用协议、域名和解析后 IP 白名单
XSS按输出上下文编码；富文本使用白名单清洗；敏感 Cookie 使用 HttpOnly 和 SameSite

五、复盘与资料

Pikachu 的关卡数量并不等于漏洞数量。真正需要掌握的是几个可复用的判断： 用户输入最终进入了什么解释器；信任边界是在浏览器、服务端、数据库还是文件系统； 当前响应能提供什么证据；以及一次利用能否被拆成更小的可验证原语。

暴力破解、XSS、CSRF 和 SQL 注入的逐题过程仍保留在 Pikachu 文章索引的 task01—task18。 本页作为关卡编号之外的总览，记录剩余模块的验收、防护边界和整场复盘。

本地验收完成：91 个 vul/ PHP 入口无异常状态；攻击链获得实际回显； 防护型关卡没有被伪造为绕过；测试数据与上传物已清理。
