Upload-Labs Pass-10：黑名单遗漏 .phar 解析扩展名

Upload-Labs Web File Upload PHP .phar

Pass-10 的黑名单很长，覆盖了常见的 .php、.phtml、.pht、.htaccess 和 .ini，但仍然遗漏了 .phar。当前 Apache 的 PHP 处理器匹配 \.ph(?:ar|p|tml)$，所以该后缀仍会被解释为 PHP。

验证状态：上传 pass10_probe.phar 成功，访问后返回 SAFE_MARKER_OK。

一、黑名单与实际解析集合不一致

$deny_ext = array(
  ".php", ".php5", ".php4", ".php3", ".php2",
  ".html", ".phtml", ".pht", ".htaccess", ".ini", ...
);

程序在比较前会统一小写、去除尾随点、去除 ::$DATA 并去空格；这些归一化处理没有直接错误。问题在于最终安全策略仍然是有限黑名单，而 Apache 的处理器可识别集合没有同步。

本机 /etc/apache2/mods-available/php8.4.conf 中的规则为：

<FilesMatch "\.ph(?:ar|p|tml)$">
    SetHandler application/x-httpd-php
</FilesMatch>

二、复现

curl.exe -sS \
  -F "upload_file=@safe-marker.txt;filename=pass10_probe.phar;type=application/octet-stream" \
  -F "submit=上传" \
  "http://127.0.0.1:8081/Pass-10/index.php"

响应中的路径原样保留为 upload/pass10_probe.phar。访问该路径得到：

SAFE_MARKER_OK

这说明黑名单、文件保存和 Apache 解析三个环节可以连成完整链路。

三、根因

漏洞不是出在“大小写或尾随字符没有被处理”，而是安全判断仍采用允许集合的补集。黑名单必须枚举所有危险后缀，但 Web 服务器和 PHP 的处理器集合会随版本、模块和配置变化，二者天然容易失配。

四、修复建议

  • 把上传类型改为明确白名单，并检查最终的服务器端文件名。
  • 不要使用客户端扩展名；业务需要图片时固定保存为 .jpg 或 .png。
  • 验证真实内容并重新编码图片。
  • 上传目录只允许静态访问，禁止 PHP、CGI、SSI 等处理器。

五、复盘

Pass-10 和 Pass-03 都说明，黑名单测试不能只看源码里列了哪些字符串，还要看目标 Web 服务器实际会执行哪些扩展名。.phar 是现代 PHP 环境中很容易遗漏的一个样本。
