Upload-Labs Pass-20：save_name 数组与尾随点兼容边界

Upload-Labs Web File Upload 数组绕过 PHP 8.4

Pass-20 从 POST 的 save_name 取保存文件名，再调用 pathinfo() 提取扩展名。经典绕过依赖把 save_name 变成数组，并利用数组长度和首尾元素的差异构造带尾随点的文件名。

验证边界：当前 PHP 8.4 对 pathinfo(array) 抛出类型错误，稀疏数组和连续数组请求都返回 HTTP 500。本文记录经典利用模型，但不宣称当前环境已经完成绕过。

一、源码

$file_name = $_POST['save_name'];
$file_ext = pathinfo($file_name, PATHINFO_EXTENSION);

if (!in_array($file_ext, $deny_ext)) {
    $img_path = UPLOAD_PATH . '/' . $file_name;
    move_uploaded_file($_FILES['upload_file']['tmp_name'], $img_path);
}

程序没有验证 save_name 一定是字符串，也没有做路径规范化和最终名称重建。

二、经典数组模型

一种旧版构造使用稀疏数组：

save_name[0] = pass20_probe.php
save_name[2] = jpg

扩展名检查看到最后一个元素 jpg；后续拼接使用 reset($file) 和 $file[count($file) - 1]，可能生成以 .php. 结尾的名称。Windows 文件系统会规范化尾随点，历史上因此可能回到 .php。Linux 不会自动删除尾随点，所以即使代码路径成立，也不能直接推断脚本会执行。

三、当前实测

分别发送稀疏数组和连续数组：

PASS20_SPARSE=500
PASS20_CONTIG=500

PHP 8 不再接受数组传给需要字符串的 pathinfo()，请求在类型检查阶段结束。上传目录没有新增 Pass-20 测试文件。

四、修复建议

  • 明确拒绝数组、对象和嵌套输入，只接受单个字符串字段。
  • 不要使用客户端保存名；服务端生成随机名称和安全扩展名。
  • 检查规范化后的完整路径，拒绝尾随点、空格、分隔符和控制字符。
  • 上传目录禁止脚本执行。

五、复盘

Pass-20 同时体现了输入类型混淆和平台语义差异。源码中的数组拼接思路值得审计，但当前 PHP 8.4 与 Linux 环境分别阻断了类型处理和尾随点执行假设，必须分开记录。
