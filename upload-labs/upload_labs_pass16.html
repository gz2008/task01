Upload-Labs Pass-16：exif_imagetype() 图片马

Upload-Labs Web File Upload exif_imagetype 图片马

Pass-16 改用 exif_imagetype() 检查图片类型。这个函数比手工读取两个字节更可靠，但仍只识别文件头，不检查或清理文件尾部的 PHP 代码。

验证状态：JPG、PNG、GIF 三种探针均通过 exif_imagetype()，通过文件包含页执行后均返回 IMAGE_INCLUDE_OK。

一、校验逻辑

$image_type = exif_imagetype($tmp_file);
switch ($image_type) {
    case IMAGETYPE_GIF:  return "gif";
    case IMAGETYPE_JPEG: return "jpg";
    case IMAGETYPE_PNG:  return "png";
    default: return false;
}

通过后，服务端用随机数字加安全图片扩展名保存，但没有对文件内容二次处理。

二、图片马构造与上传

三种合法图片末尾追加同一条固定输出语句：

<?php echo "IMAGE_INCLUDE_OK"; ?>

上传后的文件仍是可识别图片，直接访问不会执行 PHP。靶场自带 include.php，用其读取上传文件时，PHP 解释器会处理尾部代码。

三、实测结果

格式上传结果包含后
JPG成功IMAGE_INCLUDE_OK
PNG成功IMAGE_INCLUDE_OK
GIF成功IMAGE_INCLUDE_OK

四、根因

exif_imagetype() 提高了“文件头是否像图片”的判断准确度，却不会证明文件只包含图片。只要业务同时存在文件包含、模板读取或其他解释器入口，附加脚本仍可能被执行。

五、修复建议

  • 完整解码并重新编码图片，丢弃未知段和尾随数据。
  • 固定服务端输出格式和文件名。
  • 上传目录不得被 PHP 包含，也不应允许脚本处理。
  • 对图片服务使用静态域名和严格的响应头。

六、复盘

从 Pass-14 到 Pass-16，校验函数逐渐变强，但三个关卡都倒在同一件事上：只检查开头，不重建文件。修复必须从“重新生成可信文件”出发，而不是继续叠加文件头判断。
