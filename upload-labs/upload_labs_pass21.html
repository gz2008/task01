Upload-Labs Pass-21：MIME 与数组文件名绕过边界

Upload-Labs Web File Upload MIME 数组绕过

Pass-21 先信任客户端声明的 MIME，再允许 POST 的 save_name 覆盖保存名。代码对数组使用 end() 和 reset()，并通过 count() 计算最后一个元素。

验证边界：当前 PHP 8.4/Linux 下，稀疏数组请求返回“文件上传成功”，实际生成 pass21_probe.php.。数组校验与拼接缺陷已复现，但尾随点没有被 Linux/Apache 当作 .php 执行。

一、核心逻辑

$allow_type = array('image/jpeg', 'image/png', 'image/gif');
if (!in_array($_FILES['upload_file']['type'], $allow_type)) {
    $msg = "禁止上传该类型文件!";
} else {
    $file = empty($_POST['save_name'])
          ? $_FILES['upload_file']['name']
          : $_POST['save_name'];

    if (!is_array($file)) {
        $file = explode('.', strtolower($file));
    }

    $ext = end($file);
    $allow_suffix = array('jpg', 'png', 'gif');
    $file_name = reset($file) . '.' . $file[count($file) - 1];
}

两个信任边界同时存在：MIME 来自客户端，数组的键和长度也来自客户端。

二、稀疏数组请求

发送文件时使用合法 GIF MIME，并提交稀疏数组：

upload_file = valid.gif
upload_file[type] = image/gif

save_name[0] = pass21_probe.php
save_name[2] = gif

end() 看到 gif，扩展名白名单通过；count() 为 2，代码读取不存在的下标 1，最终名称成为 pass21_probe.php.。本次实测响应为：

提示：文件上传成功！

上传目录中的结果：

pass21_probe.php.  81 bytes

三、为什么还没有形成执行

Linux 把最后那个点当作文件名的一部分，不会像部分 Windows 路径处理那样自动去掉尾随点。Apache 的 PHP 规则要求路径以 .php 等后缀结束，因此 pass21_probe.php. 没有被直接交给 PHP。数组绕过与最终代码执行之间还存在平台处理差异。

四、修复建议

  • 拒绝数组输入，只接受单个受控字符串。
  • 不信任客户端 MIME；检查真实内容和扩展名白名单。
  • 服务端重新生成文件名，不使用 save_name。
  • 拒绝尾随点、空格和控制字符，并校验规范化后的真实路径。

五、复盘

Pass-21 比 Pass-20 更适合观察“部分成功”：请求确实越过了 MIME 和数组扩展名检查，也真实写出了带尾随点的文件；但当前平台没有把它映射为 PHP。把“上传成功”和“代码执行成功”分开记录，结论才可靠。
