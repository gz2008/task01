Upload-Labs Pass-19：旧式上传类与 PHP 8 构造兼容边界

Upload-Labs Web File Upload PHP 代码审计

Pass-19 使用一个独立上传类 MyUpload。关卡要求审计类里的上传顺序、扩展名判断和目标路径，而不是只看页面表单。

验证边界：当前 PHP 8.4 中，类仍使用旧式同名构造方法 function MyUpload(...)。PHP 8 不再把它视为构造函数，上传对象状态没有初始化，页面返回“不能上传到临时目录”。因此本次没有取得可执行文件。

一、旧式构造方法

class MyUpload {
    function MyUpload($file_name, $tmp_file_name, $file_size, $rename_to = '') {
        $this->cls_filename = $file_name;
        $this->cls_tmp_filename = $tmp_file_name;
        $this->cls_filesize = $file_size;
        $this->cls_file_rename_to = $rename_to;
    }
}

PHP 4/5 支持同名构造方法。PHP 8 要求 __construct()；没有它时，new MyUpload(...) 创建的对象仍保留默认空属性。随后 is_uploaded_file('') 返回失败，页面显示：

这个文件不能上传到服务器的临时文件存储目录。

二、类中的上传链

如果构造函数正常执行，类会依次检查：

  1. 临时文件是否真的是上传文件。
  2. 上传目录是否可写。
  3. 最后一个扩展名是否在允许数组中。
  4. 文件大小是否超限。
  5. 是否移动成功，以及是否需要重命名。

允许数组包含 .gif、.jpg、.png、.html、.xml 等类型，说明它仍是用扩展名决定信任，而不是根据业务场景只允许图片。

三、当前环境结论

项目结果
旧式构造方法PHP 8.4 不执行
临时文件检查对空路径失败
上传/落盘未进入移动阶段
代码执行未验证

这一类差异应在实验信息中记录为“源码与运行时兼容问题”，不能把旧版教程中的成功结果直接复制到现代 PHP 环境。

四、修复建议

  • 使用 __construct() 并显式校验全部属性。
  • 只允许业务需要的扩展名，不接受客户端文件名和目标路径。
  • 由服务端生成文件名，保存后再次校验真实路径。
  • 上传目录关闭脚本执行，并通过受控下载接口访问。

五、复盘

Pass-19 提醒我们，代码审计必须同时核对源码语义和运行时版本。同名构造方法看似存在，实际在当前 PHP 中不会初始化对象；实验结论应当以实际请求和错误信息为准。
