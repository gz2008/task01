Upload-Labs Pass-05：.user.ini 上传与 mod_php 生效边界

Upload-Labs Web File Upload .user.ini PHP

Pass-05 维护了一份很长的黑名单，但漏掉了 .ini，因此目录级配置文件 .user.ini 能通过扩展名检查。经典利用思路是在其中写入 auto_prepend_file，让同目录的 PHP 请求先包含一个图片探针。

验证边界：本机成功上传 .user.ini 和同目录图片，但 Apache mod_php 没有应用该配置；访问 upload/readme.php 未出现探针标记。因此本文只认定“配置文件可上传”，不宣称当前环境已经完成配置注入。

一、上传缺陷

本关最终仍使用客户端文件名保存：

$deny_ext = array(".php", ".php5", ".phtml", ".htaccess", ...);
$file_name = trim($_FILES['upload_file']['name']);
$file_ext = strtolower(strrchr($file_name, '.'));

if (!in_array($file_ext, $deny_ext)) {
    move_uploaded_file($_FILES['upload_file']['tmp_name'],
                       UPLOAD_PATH.'/'.$file_name);
}

.user.ini 的最后一个点是 .ini，而列表没有包含它。实际请求确认文件被保存为 upload/.user.ini。

二、经典利用链

测试配置只引用一个固定文本探针：

auto_prepend_file=/home/ctf/labs/upload-labs/upload/pass05_probe.jpg

随后上传名为 pass05_probe.jpg 的文件，正文为：

<?php echo "PASS05_PREPEND_OK"; ?>

如果运行环境会读取目录级 .user.ini，访问同目录的任意 PHP 文件时，探针应先执行。这里请求 /upload/readme.php 后，响应仍然只有 readme 的原始说明文本，没有出现 PASS05_PREPEND_OK。

三、为什么当前环境没有生效

当前靶场通过 Apache 模块运行 PHP 8.4。目录级 .user.ini 的典型生效模型是 PHP-CGI/FastCGI；mod_php 下不能把该文件当作 .htaccess 的等价配置入口。配置文件虽然进入了 Web 目录，但没有改变当前 SAPI 的 auto_prepend_file。

阶段实测结果
上传 .user.ini成功落盘
上传图片探针成功落盘
访问同目录 PHP未加载探针
当前环境代码执行未验证

四、修复建议

  • 拒绝点开头的隐藏文件以及所有配置类文件。
  • 采用扩展名白名单，不接受客户端提供的最终文件名。
  • 上传目录关闭目录级配置覆盖和脚本执行。
  • 将业务文件放到 Web 根目录之外，通过受控下载接口读取。

五、复盘

Pass-05 的价值在于提醒我们：黑名单同时遗漏了文件类型和运行模式的组合条件。写实验记录时要先确认 Web SAPI、目录配置机制和脚本执行路径，再判断某个技巧是否真的能生效。
