本题的关键是先确认输入落在字符串、数字、括号、请求头还是其他 SQL 子句中，再决定闭合与读取方式。

漏洞分析

先通过 UNION 验证三列查询。文件写出通常使用 INTO OUTFILE，但本次容器返回 SQL 错误且没有生成目标文件。

利用与验证

id=0')) union select 1,2,3-- -
页面出现 You are in.... Use outfile......，证明闭合、列数和 UNION 均正确。
实测备注：实测环境受 MySQL 账号权限或 secure_file_priv 限制，INTO OUTFILE 未成功；不对该限制作超出响应的推断。

修复建议

  • 使用 PDO 或 mysqli 预处理语句绑定参数，禁止把输入直接拼接进 SQL。
  • 对数字型参数做整数转换和范围校验；字符串参数明确类型与最大长度。
  • 关闭生产环境的 SQL 详细报错，避免库名、表名和语法结构泄露。
  • 数据库账号遵循最小权限，禁用不必要的多语句、FILE 和跨库能力。
